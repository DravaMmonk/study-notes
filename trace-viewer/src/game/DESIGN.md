# 视觉完备（Vision Complete）设计文档

一套网页端解谜／通关游戏，把 COMP90086 的学习路线做成关卡。目标是：**不靠讲解文字和图片，只靠游戏机制本身**，让玩家亲手体会计算机视觉怎样运作，以及做视觉需要的思维方式。

## 1. 研究：《图灵完备》的关卡设计在做什么

资料来源：官方战役关卡数据的镜像仓库（[michalusio/tc_campaign](https://github.com/michalusio/tc_campaign)，每关含 `meta.txt` 说明、`test.si` 测试脚本），社区 wiki，以及 Ohio Northern University 的 ASEE 2024 论文（McKanna & Hassan）。从关卡数据里能直接读出以下设计手法：

| 手法 | 在《图灵完备》里的样子 | 证据 |
| --- | --- | --- |
| 一个原件起步，其余全靠自己搭 | 第 2 关只给 NAND，之后 NOT、AND、XOR……全部由玩家用 NAND 搭出来 | `nand_gate` 解锁 `com_nand_bit`，过场语："With this component you can build everything else" |
| 先摸清原件，再用它 | NAND 关不让你搭电路，而是让你自己填出它的真值表 | `nand_gate` 的说明："figure out how the NAND component works" |
| 规格 + 自动测试 | 每关一个 `get_input` 生成测试、一个 `check_output` 判定；小问题穷举（真值表），大问题用伪随机（加法器跑 65536 组） | `xor_gate`、`byte_adder` 的 `test.si` |
| 失败就给出失败的那一组 | `tick_past_fail` 让模拟停在出错的那一拍，玩家看见具体哪组输入不对 | 几乎每关都有 |
| 过关即解锁元件（抽象阶梯） | 搭好 NOT 之后获得一个现成的 NOT 元件；后面的关卡只用它，不再关心内部 | `unlocks_components = [com_not_bit]` |
| 界面功能逐步解锁 | 关卡地图、个人页、线的颜色、注释等界面功能也是过关后才出现，开局界面极简 | `unlocks_special = ["level_map"]` 等 |
| 约束关逼出洞见 | “最多 3 个元件判断奇数个输入”逼你发现 XOR 可以串联；成就“只用 4 个 NAND 搭 XOR” | `odd_number_of_signals`：`get_component_count() > 5` 则失败 |
| 故意让你犯错 | “循环依赖”一关要求你造出非法电路，亲眼看它为什么不行，下一关再给出合法的例外（延迟线） | `dependency` 的台词：“先骗学生做错事，再取笑他们” |
| 评分但不强制 | 过关后才显示元件数、延迟，并给出分布；优化留给想挑战的人 | `score` 关、成就 |
| 应用关做回报 | 迷宫机器人、汉诺塔、排序、和 AI 打牌：用自己造的计算机解决一件真事 | `maze`、`tower`、`sort`、`ai_showdown`，`kind = architecture` |
| 熟练度小游戏 | 限时把十进制转二进制、十六进制 | `binary_racer`、`hex_racer` |
| 极少的文字 | 每关说明通常只有一两句目标，加一个可选“提示”链接 | 各关 `dialogue` |
| 技能树而非直线 | 关卡按逻辑门、算术、存储、架构分区，靠前置关系连成树 | ASEE 论文图 1 “Main Skill Tree” |

论文还指出它的价值在于“边实验边形成直觉，然后课堂再给出方法论解释”，以及用规模化问题（从 4 位推广到 32 位）逼出更好的抽象。

## 2. 映射：把这些手法搬到计算机视觉

| 《图灵完备》 | 视觉完备 |
| --- | --- |
| 原件 NAND | **平移（把整张图挪一格）** + **逐像素加、乘系数**。模糊、差分、卷积、Sobel、Harris、视差搜索都能由它们搭出来 |
| 线上的高低电平实时着色 | 每个节点实时显示它输出的小图；鼠标悬停看任意像素的数值 |
| 真值表测试 | 一组测试图（台阶、斑点、棋盘、噪声、字母、斑马板……）+ 参考输出，误差在容差内才算对；失败时并排显示输入、期望、实际和误差图 |
| 元件数／延迟评分 | 节点数／**计算量**（每像素乘加次数）评分，直接引出可分离滤波、图像金字塔、“为什么先降采样再处理” |
| 约束关 | “最多 4 个节点做 3×3 模糊”逼出可分离；“只准用均值模糊做出高斯”逼出“重复平滑趋向高斯” |
| 故意犯错关 | 直接隔点降采样斑马板，测试失败、出现莫尔纹，玩家自己发现要先模糊（抗混叠） |
| 应用关 | 书封面定位、双目测距避障、数字分类、角点跟踪 |
| 熟练度小游戏 | “核速判”：看输入输出，限时选出用了哪个核；“视差速判”等 |

**要让玩家练出的思维能力**（每关至少练一项）：分解与组合、线性叠加、局部性与参数共享、不变性、鲁棒估计（共识）、搜索换约束、概率与次数、用优化代替手工设计、权衡（精度／计算量／噪声）、抽象。

## 3. 核心机制

1. **图像流水线编辑器（主机制，对应电路编辑器）**：画布上放节点、连线；输入节点是关卡给的相机，输出节点是要通过测试的显示屏。图是无环的，连出环会被拒绝。所有测试实时跑，改一根线立刻看到每个节点的输出小图和每组测试的对错。
2. **旋钮与训练（第 4 章起）**：带参数的节点（卷积核、阈值）可以手调；“可学习核”多一个“训练”按钮，每按一次沿损失下降方向走一步，并画出损失曲线。玩家先手调、再看机器自己调，体会“学到的特征取代手工设计”。
3. **专用机关台（几何与概率章节）**：针孔暗箱、双目、极线、RANSAC 这类问题用专门的交互台：拖动小孔、选基线、设定抽样次数后跑 200 次试验看成功率。
4. **速判小游戏**：每章一个，限时选择，练直觉。

所有关卡：一两句目标；可选“提示”；过关后一句“刚才发生了什么”的点题（post-mortem），并解锁元件。

### 显示方式：数据长什么样就怎么画

电路里传的都是一格格数字，但不必都画成像素画。固定卡片不再叫相机、显示屏，而是「输入」「输出」，并标出它们装的是图像、波形还是数值。卡片和测试面板都按数据的形状选画法：

- **一个数**（1×1）：读数；测试面板把期望值、允许范围和你的输出画在同一条刻度上。
- **一行**（N×1）：波形；测试面板把期望曲线、允许带和你的输出叠在一张图里。
- **二维**：五种画法。
  - 像素：亮度即灰度。
  - 地形：亮度即高度。模糊把山削圆，边缘是悬崖，导数是山脊（正）和沟（负）。
  - 坡度：等高线加每个像素的梯度箭头。箭头指向变亮最快的方向，越长越陡，并且与等高线垂直。
  - 剖面：图上一条扫描线，以及这一行的亮度曲线。在图上拖动可以换一行。所有卡片和测试面板共用同一行，可以沿着电路一路追踪。测试面板把期望和输出的这一行叠在一张图里。
  - 频谱：中心是频率 (0, 0)，亮格 (kx, ky) 表示有一道强的波。悬停可以读出频率。

**切换方式：**
- 每张卡片右上角标着当前画法，点开是带说明的菜单。
- 画布左下角的「全部画成」一次切换所有图像卡片，旁边的按钮恢复关卡默认。
- 测试面板的切换与输入、输出卡片同步。
- 画法随电路保存，但不会重跑测试。

波形上指向或点按任意一点，会显示它的位置和数值（测试面板里还有期望值）。

关卡里左侧有关卡列表，可以直接换关（宽屏常驻、可收起，窄屏和手机是抽屉）。每次从未通过变成通过都会弹出通过窗口，不只第一次。

关卡用 `views: { in, out, mid }` 指定默认画法：求导、梯度、角点类关卡的输入默认用坡度，输出默认用地形。2-3 频率探针是一条波形进、一个数出。

### 第 2 章 · 频率（第 4 讲、作业 1）
| 关 | 名称 | 玩家要做的事 | 机制教会什么 | 解锁 |
| --- | --- | --- | --- | --- |
| 2-1 ★ | 一道波（机关台） | 四条目标条纹逐条对齐：先只有频率旋钮，再加振幅和平均亮度，再加相位；最后一条是斜纹，要调 kx、ky，箭头和频率平面上的点跟着动 | 一道波 = c、A、k、φ；二维波有方向，条纹垂直于 (kx, ky) | 波 |
| 2-2 ★ | 叠加（机关台） | 九根推杆（平均亮度 + 频率 1–8 的正弦）拼出两道波、方波、模糊后的方波；误差曲线提示缺哪一根 | 任何曲线都是波的和；陡边要高频（奇次、1/k 递减）；模糊 = 压低高频 | — |
| 2-3 ★ | 频率探针 | 用波、相乘、全图平均、平方、开方搭出“测 kx = 3 的振幅”；相位错开的测试让只用 cos 的探针失败 | 傅里叶系数 = 与 cos、sin 的内积；振幅与相位无关 | 频谱视图 |
| 2-4 ★ | 看频谱 | 把 6 张图与 6 个频谱配对；试验台上转、压条纹看亮点怎样动 | 频谱 = 每个 (kx, ky) 的探针读数；粗细 ↔ 远近，方向垂直 | — |
| 2-5 ★ | 调音台（机关台） | 给一行带噪点的像素逐频率设增益，让输出与目标重合；同时显示等效的空间核 | 频域相乘 = 空间卷积；一刀切的核有负瓣 → 振铃；高斯增益 ↔ 高斯核，σ = N/(2πR) | 频域滤波 |
| 2-6 ★ | 低通 | 用频域低通去噪；硬边掩膜引起振铃而超差 | 二维的调音台：按到中心的距离取增益 | — |
| 2-7 ★ | 采样（机关台） | 找出采到的点和 k = 3 一样的频率；找出能看对 k = 5 的最少点数；采样前选保留哪些频率 | 混叠：k 冒充 M − k；M > 2k；先低通再采样 | 降采样 |
| 2-8 ★ | 缩小一半 | 用“隔点取样”把斑马板缩小，直接取样出现莫尔纹；先模糊再取样才通过 | 抗混叠必须在采样前 | — |
| 2-9 ★ | 混合图像 | A 的低频 + B 的高频，远看近看各是一张图 | 应用关；高通 = 原图 − 低通 | — |

第 2 章的元件都先在机关台上“拆开”过：2-1 调出的波成了「波」元件，2-3 搭出的探针对每个频率都做一遍就是「频谱」，2-5 的增益曲线按半径转一圈就是「频域低通」，2-7 的采样实验解释了「隔点取样」为什么会出错。

### 第 3 章 · 光与边（第 5 讲）
| 关 | 名称 | 玩家要做的事 | 机制教会什么 | 解锁 |
| --- | --- | --- | --- | --- |
| 3-1 ★ | 斜着照（机关台） | 转灯让瓷砖亮度减半；三块瓷砖各用一种原因（转灯、调灯、换漆）达到同一亮度；同样亮的两块，推出各刷什么漆 | 亮度 = 灯强 × 反射率 × cos θ；侧视图里斜光铺得更开；照片只留下乘积 | — |
| 3-2 ★ | 颜色是三个数（机关台） | 用十根波长推杆调出目标颜色；黄光推杆坏了也调出黄色；换灯找出能分开两块「同色」布的那盏 | 三种感光把光谱压成 R、G、B；同色异谱；换光源露馅；颜色空间只是换坐标 | — |
| 3-3 ★ | 一个亮度不够（机关台） | 在按灯光着色的「朝向盘」上拖动，让亮度对上照片；再找一个很不一样的朝向；开第二盏灯后两张照片同时对上 | 一个亮度只给出与灯的夹角，等亮的朝向是一整圈；多盏灯才确定（光度立体） | — |
| 3-4 ★ | 阴影还是颜色 | 已知照片和光照图，输出表面本来的颜色；一面纯色墙上的阴影边要消失 | 照片 = 颜色 × 光照，相除分离；边缘 ≠ 物体轮廓 | — |
| 3-5 ★ | 坡有多陡（机关台） | 在斜坡、山坡、斜边上用横、竖两条剖面量出 gx、gy，合成箭头 | 梯度是指向变亮最快方向的箭头；长度是陡度；在边上垂直于边 | — |
| 3-6 ★ | 梯度大小 | 用两个 Sobel、平方、相加、开方得到每个像素的箭头长度 | 边缘强度与方向无关 | 梯度幅值 |
| 3-7 ★ | 整体变亮（机关台） | 整体加亮、灯暗一半，看边缘图怎样变；只调门槛把边找全 | 加常数不改坡度（不变）；乘系数把坡度一起缩放，固定门槛失灵 | — |
| 3-8 ★ | 关灯也认得（不变性） | 测试图被整体变亮、变暗、加偏置；边缘检测结果必须不变 | 差分去掉偏置，除以最陡的坡度去掉增益 | 归一化 |

第 3 章按第 5 讲的顺序，假设玩家完全没接触过计算机视觉：先弄清亮度和颜色从哪来、为什么一张照片推不出朝向和光照，再用剖面量出「坡度」，最后才把它们做成不怕灯光变化的边缘检测器。原来的「朗伯台」讲的是同一件事（反射率和灯的方向分不开），但一次塞了太多未知量，已由 3-1 和 3-3 取代。

## 5. 技术结构

- 位置：`trace-viewer/game.html` + `src/game/`；第二期关卡以“关卡包”形式放在 `levels/pack-*.js`，机关台组件在 `ui/boards/`，与 Fieldnotes 共用构建和主题色；Fieldnotes 顶栏有入口。
- `engine/image.js`：小尺寸浮点图像（默认 16×16）、测试图库、比较与误差。
- `engine/nodes.js`：节点类型注册表（输入、输出、端口、参数、计算、计算量）。
- `engine/graph.js`：拓扑排序、环检测、求值、节点数与计算量统计。
- `levels/*.js`：关卡为纯数据 + 测试生成函数；`levels/index.js` 汇总关卡包并给出前置关系。每个搭电路的关卡带预期解法与天真解法，每个机关台带 `verify()`，`npm run levels` 逐一验收。
- `ui/`：关卡地图、编辑器、测试面板、图像查看器、对话框。
- 存档：浏览器 `localStorage`（已解决关卡、每关的图、最佳分数）。
