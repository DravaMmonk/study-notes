# 区块与紧凑排版：开发文档

给接手实现的会话。先读 `games/DESIGN.md` 第 6.10 节的 **Pipeline sections** 和 **Player settings** 两段（分段来历、分割线、原位折叠、淡底、设置面板都已做完，最近的提交到 `b505153`），再读本文。本文做三件事：把分割线改成**区块**，给区块三档显示，并给整块板定一套**紧凑排版规则**；同时**去掉「整理」**。

## 1. 现状的问题

- **组和组之间摆得很散。** 桌面上「核方向」和「邻域加权」隔着大半个屏幕，连线上千像素；组按依赖深度各占一列，中间留出大片空白；这一关新放的常数排在最底下，离用它的地方很远；链里的卡片高低略有差，线有小折角。`circuit/layout.js` 的 `flowLayout` 只按深度分列、逐个往下堆，没有组的概念，也不对齐口。
- **手机紧凑视图里线乱穿。** 输入卡片在最上面，线穿过好几个分节伸到下面；口名浮在卡片上方；分节里还夹着「+」空格。
- **分割线只能按行切，**而且整块板必须从头切到尾，不能「一部分分区、其余不分」。

## 2. 设计

### 2.1 区块（替换分割线）

- 数据：`board.blocks: [{ id, note?, view, nodes: [node id] }]`，替换 `board.sections`（硬切换：删掉分割线的读写、`circuit/sections.js`、`circuit/SectionLine.jsx`、窄边里的「＋」和拖动把手）。开发阶段存档不迁移，旧存档里的 `sections` 不再读。
- 一个元件最多在一个区块里；**可以不在任何区块里**，区块和散放的元件同时出现。关卡给的输入、输出卡片不进区块。
- 成员按元件 id 记，所以桌面和手机看到的是同一组区块。区块的外形（淡底、线）都由成员的位置算出来，区块自己没有坐标。
- 预设：板上还没有 `blocks` 时，按课程分段（`engine/stages.js`）生成，和现在分段的预设规则一样：以前各关留下的每段一个区块，批注是段名，`view: 'ports'`；这一关新放的元件不进区块。写过（包括写成空列表）就用板上的。
- 区块只影响画面：蓝图文本、运行、判定、检查都不读它（和 `x`、`y`、`slot` 一样）。删掉一个区块不动任何元件。

### 2.2 三档显示（每个区块各自选）

| 档 | `view` | 区块里的元件 |
|---|---|---|
| 全部显示 | `full` | 完整的元件卡 |
| 仅显示端口 | `ports` | 原卡去掉主体，只剩头和口（就是现在的「原位折叠」） |
| 不显示 | `hidden` | 元件不画；区块收成一条只有表头的窄条（批注、「n 个元件」、档位开关）。进出这个区块的线接在窄条边上的口桩上（桌面：左边进、右边出；手机：窄条上下沿），按 `circuit/connections.js` 的规则需要时画成成对标签；点口桩或标签就把区块切回上一次的档并定位到那个元件 |

档位开关是区块表头里的一个三段小开关（图标，配用词表里的名字作提示），桌面和手机同一个组件。单步运行走进 `hidden` 的区块时临时显示它（不写回 `view`）。

### 2.3 怎么分区

- **桌面**：画布角上的工具组（缩放那一组）加一个「分区」按钮，任何时候都能用，不受设置控制。点它进入框选：拖出一个矩形，卡片中心落在矩形里的元件（固定卡片除外）组成一个新区块，原来属于别的区块的就从那个区块移出（空了的区块随之消失）；按 Esc 或再点按钮退出。区块表头里能改批注、切档位、删除区块（元件留下）。
- **手机**：只有在设置「手动分区」打开**并且**处于紧凑视图时，工具行才有「分区」按钮。点它，先点起点所在的行，再点终点所在的行，两行之间（含）的元件组成新区块，规则同桌面。改批注、切档位、删除区块和桌面一样在表头里。
- 设置里的「手动分段」改名「手动分区」，只在手机上出现（桌面没有这项设置）。

### 2.4 手机上区块的样子

- **手动分区打开且在紧凑视图**（可以分区的状态，参照图 1 的版式）：元件是紧凑格子（窄、头 + 口），区块是淡底，表头在淡底顶上，和桌面区块同一种样子。
- **其他情况**（默认视图，或者没打开手动分区）：元件保持默认大小（参照图 2），区块不做淡底和内边距，只在区块的第一行上方、最后一行下方各画一条**从屏幕最左端到最右端**的细线；上面那条线左端是表头（批注、档位开关）。`hidden` 时两条线合成一条带表头的线。`ports` 档在默认视图里不改变元件大小（默认视图里元件一律默认大小），表现同 `full`；只有紧凑视图才有「仅显示端口」的样子。
- 区块的成员在手机上总是排在连续的行里（见 2.6 第 7 条），所以首尾两条线之间就是它的全部成员。

### 2.5 去掉「整理」

删掉按数据流整理的按钮和功能（桌面和手机都删，含撤销记录里的那一类操作）。排版规则（2.6）只在三种时候用：板第一次打开、还没有坐标时的落位；带过来的或新放进来的元件的落位；区块切换档位时**只在画面上**的让位（不写回坐标）。玩家摆过的位置从不被改写。

### 2.6 紧凑排版规则（`circuit/layout.js`）

规则固定、确定：同一块板、同样的区块和档位，算出来一样。分两层：

**区块内**

1. 按区块内的依赖分列，数据从左往右；没有分叉的链排成一行。
2. 同一列里有几个元件时，按上游元件的平均高度排上下（重心法），减少交叉。
3. **按口对齐**：下游卡片的输入口和上游的输出口放在同一高度，链里的线是直线。仅显示端口时卡片高度固定（头 + 口的行数），对齐总成立。
4. 间距只有几个数，都取 tokens（在 `kit/tokens.css` 游戏层定义，例如 `--board-gap-x`、`--board-gap-y`、`--block-pad`）：列间距够线拐一个弯，行间距、区块内边距都小；表头占内边距里的一行。

**区块之间（区块和散放元件都算一个单位）**

5. 单位按数据流排先后（单位之间的线构成依赖图），从左往右摆；一行总宽超过视口宽度就**折到下一行**，像段落换行，每行仍从左往右读。互不依赖的单位（同一上游的两路）上下叠在同一位置，不各占一列。
6. 输入卡片在最左、输出卡片在最右，照旧。常数和只接一处的源贴在它唯一下游的左边，跟着那个单位走，不进全局的第一列。这一关新放的散放元件按数据流插在它该在的位置（多半是最后），不固定放在底部。
7. **手机**：两列格位；一个区块的成员排在连续的行里，区块内先左后右、下游紧跟上游；区块之间、区块和散放元件之间按数据流的先后排行。

**稳定和线**

8. 切换一个区块的档位时，它左上角不动，排在它后面的单位按尺寸差在画面上平移；不整体重排。
9. 区块内是直线；区块之间的线从出口走到下一单位的入口，同一对单位之间的几根线并成一束；折到下一行的线从行尾绕下去，只拐两次。

**用数字验收**：给 `layout.js` 写测试（在测试里现搭的板上，不读任何一款游戏）量四个数：外框面积、最长的一根线、线的交叉数、线的总长，每个给出上限；再在报告里给出《视觉实验室》扫描仪那块板现在和改后的四个数。

### 2.7 视觉统一

- 区块的表头（批注、「n 个元件」、三档开关）只有一个组件，桌面淡底、手机淡底、手机细线三种场合共用；淡底和细线用同一组 tokens（颜色、圆角、内边距、线宽）。
- 「分区」按钮和画布、工具行上其他按钮同一种样式；框选矩形、起点行和终点行的高亮用同一种强调色。
- 新的用词（分区、全部显示、仅显示端口、不显示、n 个元件）放进 `kit/shell/words.js`，两端都从那里取。
- 不加次要的标签和说明（DESIGN 第 6.10 节）；样式只取 tokens，`npm run styles` 不升。

## 3. 步骤

每步一次提交，直接推到 main（先 `git pull --rebase`）。每步跑第 5 节的验证。

- **3a 排版规则**：`circuit/layout.js` 按 2.6 重写（区块和散放元件作单位、对齐口、折行、并列叠放、常数贴下游），四个数的测试；初次落位、新元件落位、档位切换的画面让位都改用它；`svg.js` 的输出若因此变化，更新它的测试并在报告里说明。
- **3b 区块数据**：`board.blocks` 的读写、预设、成员规则（新区块拿走别人的成员、空区块消失）、三档；删掉分割线全套。配单元测试（预设、框选取成员、起止行取成员、删区块不动元件、蓝图文本不含区块、显式空列表不再生成预设）。
- **3c 桌面**：画布「分区」按钮和框选；区块表头和三档；`hidden` 的窄条、口桩和标签。
- **3d 手机**：两种样子（2.4）；手动分区 + 紧凑视图下的「分区」按钮和起止行选择；三档。
- **3e 去掉「整理」**，设置项「手动分段」改为只在手机出现的「手动分区」。
- **3f 文档**：DESIGN 第 6.10 节 **Pipeline sections** 改写成区块（数据、三档、怎么分区、两端的样子、排版规则、没有「整理」），**Player settings** 改名；本文件做完后删掉，`games/PLAN.md` 进度记一行。
