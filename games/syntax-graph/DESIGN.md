# 句法之图 Syntax Graph · 设计

这份文档只讲本专题的内容。共同的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；引擎在 `games/kit/domains/syntax`。

## 1. 终点与定位

**终点**：理解并主动使用英语母语者组织一句话时的隐性思维，写出地道、准确、精简的计算机学术英语（论文正文、实验结论、审稿往来）。后期关卡要难到母语作者也能从中学到东西。

**不教基础语法。** 词形、一致、格、助动词这些规则全部交给机器：玩家不选 *has* 还是 *have*、*we* 还是 *us*，机器按主语和位置配好。会这些规则的学习者已经很多，写出来的英语却仍然不像母语者写的，差距在于规则之外的决定。

**教母语者开口之前的决定。** 以中文为母语的学习者，恰好在这些地方和英语的思路相反：

| 决定 | 母语者先问的问题 | 中文思路的常见偏差 |
|---|---|---|
| 时间和视角 | 这件事什么时候的？站在哪里看：整件事、留下的结果、进行中的一刻？ | 不标时间，靠上下文；先想到动词再回头变形 |
| 谁当主语 | 这句话说的是谁？让“角色”当主语、“动作”当动词 | 话题—评论结构（“这篇论文，我们改了三次”）；名词化堆砌 |
| 读者认得出吗 | 读者能认出我说的是哪一个吗？a / the / 复数 / 不加 | 当成语法规则去背，或干脆不加 |
| 旧在前，新在后 | 句首接上文，新的、重的放句尾 | 按事情发生的顺序或中文语序排 |
| 中心词在前 | 先说是什么，修饰放在后面（*the method we propose in Section 3*） | 长定语全堆在名词前面 |
| 主次分明 | 一句一个主干，其余挂成从属成分 | 逗号把几个小句并排串起来 |
| 断言有多强 | *shows* / *suggests* / *may* 各承诺多少 | 语气词堆叠或一律绝对 |

**场景**：全部取自一篇计算机论文和它的审稿：模型收敛、方法优于基线、回复审稿人、发布代码、撤稿重投。词汇只是载体。

**依据**：时间先于词，来自说话产出的心理语言学模型（Levelt）和口误研究（词干对调而时态留在原处）；其余几条决定来自英语写作研究里有共识的部分（Williams《Style》的“角色当主语、动作当动词”，信息结构的旧—新原则和尾重原则）。每条进游戏之前都要能写成确定的判断：给定情境，哪个选择对，错的为什么错。

## 2. 核心机制

**关卡给情境和语义图，玩家做决定，机器说出句子。**

| 《图灵完备》 | 句法之图 |
|---|---|
| 真值表 / 测试 | 情境 + 语义图：谓词、参与者及其角色；时间和视角不写出来，要从情境里判断 |
| 元件 | 母语者的选择：时间和视角的三个问题（这一章），以后是主语、限定、语序…… |
| 电路板 | 按语序排好的一排位置：主语，谓语里的时间、动词、动词要的宾语 |
| 门数 / 延迟 | 词数（★ 目标），以后还有歧义解析数 |

**三层，各管一件事：**

1. **机器配形式**（`engine/grammar.js` 的 `inflect`、`said`）：时间加主语得出助动词和动词形式（*has / have*、*is / are*、*was / were*、*-s / ∅*），代词按位置取主格或宾格。主语还没放时，依赖它的形式写成两种（*has/have*）。
2. **放词只拒绝结构错误**（`refuse`）：词放错类的位置、动词没开这个位置。一致和格不再拒绝，因为不会错。
3. **运行时比对意思**（`engine/sentence.js` 的 `check`）：读回语义，与语义图逐项比对。时间和视角选错时，给的是这一关写好的理由（关卡的 `why`）：母语者为什么在这个情境里不这么说，而不是一句“说成了过去 · 一般”。`npm run check` 要求每关给它提供的每个错误时间都写一条理由。

**时间是三个问题，不是一个词块**（`grammar.js` 的 `TIME_QUESTIONS`、`timeOf`）。时间在说话人那里先是一个判断，不是一个词；玩家要练的是问对问题，所以时间位置不放成品块，而是在句子下面问：

1. 这是一次具体的事，还是不限于哪一次（规律、性质、习惯）？后者就是一般现在时，不用再问。
2. 你站在哪一刻说它：现在、过去某一刻、将来某一刻？（Reichenbach 的参照时间）
3. 从那一刻看，这件事：整件事就在那一刻 / 已经做完、结果还在 / 正在进行、还没完？

答案由机器合成时间（站在现在 + 结果还在 = 现在完成时）。站在现在看一次具体事件的“整件事”，英语里几乎不用（只在解说之类的场合），面板会说明原因，不给出时间。关卡的 `palette.time` 只决定哪些答案已经打开：后面才引入的答案先是灰的，问题本身每关都一样。

改成问题之前，块上直接写着视角（「到现在 · 结果还在」），情境里一出现“结果放在附录里”，玩家就能按字面对上，不用想。所以情境的措辞也要避开问题选项里的词，并且不复述目标句：英语那一面尤其不能写出目标时态（“the ablation has been added”）。

**时间先定，其余锁住。** 时间没定之前，主语、动词、宾语都锁着，点了会说“先回答时间的问题”。这一步有依据：时间属于意思本身，开口前就在。完整的顺序不强制：说话是边想边说的，主语常常比动词先想好，规定“时间 → 动词 → 主语”教的是母语者自己都不守的顺序。语义图把时间放在最上面，运行后才显示这里要的答案；时间定好后，空着的动词位置写出它在等的形式（「动词（过去分词）」）。

**选错时指出错在哪一问。** 运行后，时间框写出这里要的三个答案；选错时标出“错在第几问”，并给出关卡的理由，没有就用那一问的通用理由（`timeStep`）。

**过关后给最小对比。** 通关窗口把同一句话换成本关提供的每一种别的时间，由机器说出来，并配上它代表的答案（*The model fails* · 不限于哪一次）。只差时间、意思就变的句子，比规则更能练出语感。

**代词通过上下文指称。** 代词本身不指任何东西；关卡的 `refer` 写明在这一关的语境里 *we*、*they* 指谁。

## 3. 交互：词序条

句子用 kit 的**词序条**（`games/kit/strip`）搭，不用电路：小句只有四五个位置，电路的数据流方向又和语序相反。

- 一排按语序排好的位置，下面用括号标出成分；
- 点一个词，它进建议的空位或第一个能放它的空位；先点位置再点词，就放进那个位置；点已放的词把它拿掉；
- 选了动词，它要的宾语位置就接在它后面（*V NP NP* 开两个，*V NP to NP* 开一个再加 *to*）；
- 位置里显示的就是句子本身。

桌面和手机是同一套交互。

## 4. 分层：引擎与内容

这个游戏的目录里**只有规格**（见 `games/DESIGN.md` 第 6 节）：

```
games/syntax-graph/
  spec.js              课程：时代、关卡、词库、百科、存档迁移，交给 syntaxCourse
  game.js              交给领域，三行（defineSyntaxGame）
  lexicon.js           词：名词短语、代词（主格和宾格）、动词（框架、各形式）；时间是引擎的，不在词库里
  levels/viewpoint.js  第一章的关卡规格
  glossary.js          百科：玩法、机器替你做的、母语者怎么想
```

引擎在 `games/kit/domains/syntax`，对任何这类游戏都一样：

```
engine/grammar.js   位置与语序、框架、角色；时间和三个问题（TIMES、TIME_QUESTIONS）；时间加主语说出的形式（inflect）、代词的格（said）；放词规则
engine/lexicon.js   读入一个游戏的词库
engine/sentence.js  小句 → 句子与语义 → 与语义图比对（错误的时间用关卡写的理由）
engine/parts.js     词的家族（颜色）和说明
engine/course.js    规格 → 关卡、游玩顺序、课程审计（syntaxCourse）
ui/                 关卡页（情境、语义图、词序条、时间问题、词块、句子）、地图插图（排字手托，games/stick）
game.jsx            defineSyntaxGame：规格 → 外壳要的游戏描述
validate.js         npm run check：每关的参考答案、陷阱，以及每个错误时间都有理由
syntax.test.js      npm test：机器配的形式、放词规则、读句子、语义比对
```

## 5. 一关怎么写

```js
{
  id, title, brief, intro?, hint?,
  context: [{ zh, en }],                               // 情境：在哪说、接着什么说、读者知道什么
  meaning: { pred, tense, aspect, roles: { AGENT: { ent, number, label, note? }, … } },
  palette: { time: [...], np: [...], verb: [...] },    // time：本关权衡的时间（'present.perfect'），决定打开哪些答案；词：包括干扰项
  why: { <time key>: { zh, en } },                     // 每个错误时间的理由：母语者为什么在这里不这么说
  preset?: { SUBJ, V, … },                             // 已经放好、拿不掉的位置
  refer?: { we: 'author', … },                         // 代词在本关语境里指谁
  target?: 8,                                          // ★ 的词数上限
  answer: { SUBJ, TIME, V, OBJ?, IOBJ?, TO? },          // 参考答案，按位置写词库里的键
  traps: [{ answer, fails: 'grammar' | 'pred' | 'time' | 'role' | 'star' }],
  debrief: { title, body, note },
}
```

**情境不泄题。** 不复述目标句，不用问题选项里的词（结果、正在、一直），英语那一面不写出目标时态。语义图已经给出要说的事，情境只给判断所需的事实：在哪说、接着什么、现在的状况。

**情境要让答案唯一。** 一个情境里，两种时间都说得通的话，这一关就不成立；写情境时先写出每个错误选项的理由，写不出来，说明情境还不够确定。理由只讲这个情境里的判断，不讲语法名词。

**陷阱是规格的一部分。** 每一关都写出玩家最可能试的错句，并写明它在哪一层被拦下。

**一关一个新想法**（课程审计）：概念按母语者的决定划分。所有名词短语和动词算一个概念（“放词”）；每种视角（一般、完成、进行）各算一个，同一视角的不同时间是它的型号。

## 6. 第一章：时间和视角

| 关 | 新想法 | 句子 | 母语者问的问题 |
|---|---|---|---|
| 1-1 先定时间 | 教程：情境、时间先定、词形自动 | The model converged. | 已经过去了吗？ |
| 1-2 放词 | 教程：放词、位置分角色 | The committee rejected the paper. | 谁对谁做的？ |
| 1-3 补上了 | 到现在 · 结果还在 | We have added the ablation. | 结果现在还在吗，读者关心它吗？ |
| 1-4 当时怎么做的 | 练习：换方向 | We evaluated them. | 这是在讲经过吗？ |
| 1-5 可以下载了 | 练习：换外观（公告） | We have released the code. | 现在能用了吗？ |
| 1-6 又投回来了 | 练习：辨真伪 | The authors withdrew the paper. | 结果被后来的事抹掉了吗？ |
| 1-7 结论 | 一般成立（论文的两只钟） | The method outperforms the baselines. | 这是结论还是那一次？ |
| 1-8 那一次 | 练习：换方向 | The model failed. | 五次里的一次是规律吗？ |
| 1-9 定理 | 练习：换外观 | The algorithms terminate. | 它什么时候成立？ |
| 1-10 核到一半 | 正在进行（站在里面看） | We were checking the proof. | 那一刻做完了吗？ |
| 1-11 还在改 | 练习：现在，三选一 | We are updating the code. | 是习惯、做完了，还是正在做？ |
| 1-12 那时之前 | 过去完成（把“结果还在”搬到过去） | The authors had withdrawn the paper. | 站在哪一刻往回看？ |
| 专题·投稿 S1–S3 | 挂在 1-12 之后，每句三选一 | 审稿人读完了 → 周三发了答辩 → 会发终稿 | 组合：近况、经过、承诺 |

每组的最后一关是“辨真伪”或“换方向”：1-6 是现在完成时看起来最自然、其实结果已经不在的情境。

存档第 4 版把时间改成按时与体命名的键（`time:present.perfect`），草稿里的时间跟着改名。存档第 3 版做了这次改写：只保留 1-1 的通过记录，其余关卡和旧草稿都丢掉（旧草稿里存的是已经删掉的时体块）。

每一章是一个母语者的决定，按依赖排：时间定下框架；有了框架才谈主语；有了主语，才谈它和上文怎么接。

| 章 | 决定 | 新机制（引擎） | 关卡里的判断 |
|---|---|---|---|
| 2 谁当主语 | 角色当主语、动作当动词；话题—评论改成主语结构；被动是为了让该当主语的当主语 | 同一语义图的几种说法（主动、被动、名词化）由机器生成，玩家选主语 | *We evaluated X* 对 *An evaluation of X was performed*；上文一直在讲模型时为什么用 *The model was trained…* |
| 3 读者认得出吗 | a / the / 复数 / 不加，由读者能否认出决定 | 语义图标出读者已知的实体；限定词由玩家按“认不认得出”选，形式由机器配 | 第一次提到用 a，上文说过或双方都知道的用 the |
| 4 旧在前，新在后 | 句首接上文，新信息和长成分放句尾 | 情境里写出上一句；词序条允许成分移动（主题化、外置、与格交替） | *send the editor a rebuttal* 还是 *send a rebuttal to the editor*：看哪个是新的、哪个更长 |
| 5 中心词在前 | 先说是什么，修饰放在后面 | 后置修饰：介词短语、定语从句作为可放进名词短语的块 | *the method that we propose in Section 3* |
| 6 主次分明 | 一句一个主干，其余挂成从属成分 | 从句、非谓语；多个语义图合成一句 | 把三件事说成一个主干两个从属，主干放最重要的那件 |
| 7 断言有多强 | 按证据选承诺强度 | 语义图标出证据强度 | *shows* / *suggests* / *may* |
| 8 母语者关卡 | 无歧义、最精简 | 验证器枚举全部合法解析，有歧义即失败 | 悬垂修饰语、平行结构、极限精简 |

## 8. 诚实的限制

- "先定时间"用的是说话产出的模型（Levelt），不是说母语者真的等时间定好才想别的：说话是边想边说的，主语常常比动词先想好。游戏练的是“时间属于意思本身、从一开始就在”这个习惯，界面也只是提示时间先行，不强制顺序。
- 情境里的判断有边界：真实写作中不少地方两种说法都可以（比如有的结论用过去时报告，也被接受）。关卡只收答案唯一的情境，所以练出的是典型判断，不是全部用法。
- 词库是封闭的。这是解谜，不是自由写作；用词的丰富度要靠别的途径。
- 修辞上的“好”超出可量化指标，只能用词数、歧义数这类代价间接体现。
- 第 8 章的“唯一解析”取决于文法的覆盖度：文法漏掉的歧义，验证器也查不出来。
- 显性的知识向流利使用的迁移有限。这个游戏能让人在写作时问对问题，但语感的主体仍靠大量阅读。
