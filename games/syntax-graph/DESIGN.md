# 句法之图 Syntax Graph · 设计

这份文档只讲本专题的内容。共同的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；引擎在 `games/kit/domains/syntax`。

## 1. 终点与定位

**终点**：学完能亲手写出正确、准确、精简的计算机学术英语——论文正文、实验结论、审稿往来；后期关卡要难到母语作者也能从中学到东西。

**场景**：全部取自一篇计算机论文和它的审稿：模型收敛、方法优于基线、程序委员会录用论文、作者撤稿、审稿人核查证明。词汇只是载体，练的是句子结构；选这个语境，是因为目标读者真正要写的就是这些句子。

**定位**：这个游戏练的是**句法结构**和**写作表达**，不是词汇量、听力或口语。语言能力的主体靠大量输入习得，这个游戏不替代它，只负责那部分可以形式化、可以确定性验证的能力：

- 一句话能不能成立（语法：词类、一致、格、框架）；
- 它说的是不是要说的意思（语义：谓词、角色、时与体）；
- 在意思不变的前提下，它是不是更好（代价：词数，以后还有歧义数、信息流）。

## 2. 核心机制

**关卡给语义，玩家写句子。** 对应《图灵完备》的"给真值表，搭电路"：

| 《图灵完备》 | 句法之图 |
|---|---|
| 真值表 / 测试 | 语义图：谓词、参与者及其角色、时与体 |
| 元件 | 词：名词短语、时体（INFL）、动词 |
| 电路板 | 按语序排好的一排位置：主语，谓语里的时体、动词、动词要的宾语 |
| 连线的位宽 | 位置的类型和特征：主语只收主格名词短语，并要和时体一致 |
| 门数 / 延迟 | 词数（★ 目标），以后还有歧义解析数 |

**两层检查，各管一件事：**

1. **语法在放词时检查**（`engine/grammar.js` 的 `refuse`）：放不进去，并说明是哪条规则——词类、动词没开这个位置、格、主谓一致。
2. **语义在运行时检查**（`engine/sentence.js` 的 `check`）：句子成立以后，把它读回语义，与语义图逐项比对。不对的地方标红，并写出句子实际说成了什么。

所以玩家永远拼不出不合语法的句子，但很容易拼出合语法、意思却不对的句子——这正是第一关就要让人看到的：放得进，不等于意思对。

**代词通过上下文指称。** 代词本身不指任何东西；关卡的 `refer` 写明在这一关的语境里 *we*、*them* 指谁。这是对"前文已提及"的诚实建模。

## 3. 交互：词序条，而不是电路

第一版把句子当电路搭：宾语连进动词、动词和主语连进时体、时体连进句子卡片。两处不合适：

- **方向反直觉**：数据流是从下往上汇到根，和人说话、阅读的顺序（主语 → 谓语 → 宾语）不一致；
- **太重**：一棵只有四五个叶子的小句，要放卡片、拉四五根线，操作量远大于它要教的东西。

现在的交互是 kit 的**词序条**（`games/kit/strip`）：

- 一排按语序排好的位置，下面用括号标出成分（主语、谓语、小句）——树还在，只是画成括号；
- 点一个词，它进第一个能放它的空位；先点位置再点词，就放进那个位置；点已放的词把它拿掉；
- 选了动词，它要的宾语位置就接在它后面（*V NP NP* 开两个，*V NP to NP* 开一个再加 *to*）；
- 位置里显示的就是句子本身：放进 *has + -en* 和 *accept*，位置里念出 *has accepted*。

桌面和手机是同一套交互，没有拖拽，没有连线。词序条是通用组件，以后任何"按顺序搭一个序列"的专题都能用（比如命令行）；需要数据流的专题继续用电路编辑器。

## 4. 分层：引擎与内容

这个游戏的目录里**只有规格**（见 `games/DESIGN.md` 第 6 节）：

```
games/syntax-graph/
  spec.js          课程：时代、关卡、词库、百科，交给 syntaxCourse
  game.js          交给领域，三行（defineSyntaxGame）
  lexicon.js       词：名词短语、动词（框架、各形式）、时体（助动词、要求的动词形式、一致）
  levels/clause.js 第一章的关卡规格
  glossary.js      百科
```

引擎在 `games/kit/domains/syntax`，对任何语法游戏都一样：

```
engine/grammar.js   位置与语序、框架、角色、一致、格：放词规则
engine/lexicon.js   读入一个游戏的词库
engine/sentence.js  小句 → 句子与语义 → 与语义图比对
engine/parts.js     词的家族（颜色）和特征说明
engine/course.js    规格 → 关卡、游玩顺序、课程审计（syntaxCourse）
ui/                 关卡页（词序条、词块、语义图、句子）、地图插图（排字手托，games/stick）
game.jsx            defineSyntaxGame：规格 → 外壳要的游戏描述
validate.js         npm run check：每关的参考答案和陷阱
syntax.test.js      npm test：放词规则、读句子、语义比对
```

## 5. 一关怎么写

```js
{
  id, title, brief, intro?, hint?,
  meaning: { pred, tense, aspect, gloss, roles: { AGENT: { ent, number, label, note? }, … } },
  palette: { np: [...], verb: [...], infl: [...] },   // 只列这一关的词，包括干扰项
  preset?: { INFL, V, … },                             // 已经放好、拿不掉的位置
  refer?: { we: 'author', … },                         // 代词在本关语境里指谁
  target?: 8,                                          // ★ 的词数上限
  answer: { SUBJ, INFL, V, OBJ?, IOBJ?, TO? },         // 参考答案，按位置写词库里的键
  traps: [{ answer, fails: 'grammar' | 'pred' | 'time' | 'role' | 'star' }],
  debrief: { title, body, note },
}
```

**陷阱是规格的一部分。** 每一关都要写出玩家最可能试的错句，并写明它应该在哪一层被拦下。`npm run check -- syntax-graph` 会跑参考答案（必须通过、拿到 ★）和每个陷阱（必须在写明的那一层失败）。这条检查保证干扰项真的在起作用：比如 1-3 的 `-s + the algorithms` 必须在放词时就被拒绝，`-ed` 必须在时间上被判错。

**一关一个新想法**（`npm run check` 里的课程审计）：概念按语法划分——名词短语、代词（带格）、每种动词框架、每种体。同一种体的各个时态和一致形式算同一个概念的不同型号。

## 6. 第一章：小句

机体是**小句**：一个主语、一个定下时间并要求一致的时体、一个动词、动词框架要求的宾语。

| 关 | 新想法 | 句子 |
|---|---|---|
| 1-1 主语 | 名词短语 | The model converged. |
| 1-2 谓语 | 不及物动词 | The experiment failed. |
| 1-3 时与一致 | 一般体的时体（-s / ∅ / -ed / will） | The algorithms terminate. |
| 1-4 宾语 | 及物框架 | The method outperforms the baseline. |
| 1-5 完成体 | 完成体 | The committee has accepted the paper. |
| 1-6 格 | 代词 | We evaluated them. |
| 1-7 进行体 | 进行体 | The reviewers were checking the proof. |
| 1-8 三个位置 | 双宾框架（V NP NP / V NP to NP） | The committee will grant the authors an extension. ★≤8 |
| 1-9 过去的过去 | 练习 | The authors had withdrawn the paper. |
| 1-10 代码给谁 | 练习 | We have sent them the code. ★≤6 |
| 专题·投稿 S1–S3 | 挂在 1-8 之后 | 审稿人读过论文 → 作者递交答辩 → 发出终稿 |

1-1、1-2 用 `preset` 把还没教的部分（时体、动词）先放好，这样第一关只有一个新想法。

**诚实的限制：**

- 词库是封闭的。这是解谜，不是自由写作；练出的是结构能力，用词的丰富度要靠别的途径。
- 修辞上的"好"超出可量化指标，只能用词数、歧义数这类代价间接体现。
- 第 6 章的"唯一解析"取决于文法的覆盖度：文法漏掉的歧义，验证器也查不出来。那一章的文法要投入最多。
- 显性的语法知识向流利使用的迁移有限。这个游戏能让人写对、写准长难句，但不是学英语的主力工具。
- 词序条把语序固定成了标准语序。第 3 章（信息流）要让玩家自己挪动成分（主题化、外置），到时要给词序条加"可移动的成分"，而不是退回电路。
