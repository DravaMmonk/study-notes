# 句法之图 Syntax Graph · 设计

这份文档只讲本专题的内容。共同的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；引擎在 `games/kit/domains/syntax`。

## 1. 终点与定位

**终点**：理解并主动使用英语母语者组织一句话时的隐性思维，写出地道、准确、精简的计算机学术英语（论文正文、实验结论、审稿往来）。后期关卡要难到母语作者也能从中学到东西。

**不教基础语法。** 词形、一致、格、助动词这些规则全部交给机器：玩家不选 *has* 还是 *have*、*we* 还是 *us*，机器按主语和位置配好。会这些规则的学习者已经很多，写出来的英语却仍然不像母语者写的，差距在于规则之外的决定。

**教母语者开口之前的决定。** 以中文为母语的学习者，恰好在这些地方和英语的思路相反：

| 决定 | 母语者先问的问题 | 中文思路的常见偏差 |
|---|---|---|
| 时间和视角 | 这件事什么时候的？站在哪里看：整件事、留下的结果、进行中的一刻？ | 不标时间，靠上下文；先想到动词再回头变形 |
| 谁当主语 | 这句话说的是谁？让“角色”当主语、“动作”当动词 | 话题—评论结构（“这篇论文，我们改了三次”）；名词化堆砌 |
| 读者认得出吗 | 读者能认出我说的是哪一个吗？a / the / 复数 / 不加 | 当成语法规则去背，或干脆不加 |
| 旧在前，新在后 | 句首接上文，新的、重的放句尾 | 按事情发生的顺序或中文语序排 |
| 中心词在前 | 先说是什么，修饰放在后面（*the method we propose in Section 3*） | 长定语全堆在名词前面 |
| 主次分明 | 一句一个主干，其余挂成从属成分 | 逗号把几个小句并排串起来 |
| 断言有多强 | *shows* / *suggests* / *may* 各承诺多少 | 语气词堆叠或一律绝对 |

**场景**：全部取自一篇计算机论文和它的审稿：模型收敛、方法优于基线、回复审稿人、发布代码、撤稿重投。词汇只是载体。

**依据**：时间先于词，来自说话产出的心理语言学模型（Levelt）和口误研究（词干对调而时态留在原处）；其余几条决定来自英语写作研究里有共识的部分（Williams《Style》的“角色当主语、动作当动词”，信息结构的旧—新原则和尾重原则）。每条进游戏之前都要能写成确定的判断：给定情境，哪个选择对，错的为什么错。

## 2. 核心机制

游戏有三种关：**快练**（`kind: 'drill'`）、**投稿**（`kind: 'run'`，可以一直玩的模式）和**搭句子**。第一章是七关快练加一个投稿；搭句子留给结构真正重要的章节（主语、语序、从句）。

### 2.1 快练：场合 → 说法

**为什么不逐句推理。** 第一版让玩家每句回答三个问题（一次还是一直、站在哪一刻、从那一刻怎么看）再合成时态。试玩的结论是：懂时态含义的人，三个问题只是把已经懂的东西再显式推一遍，练的仍是理解，不是习惯；而推理再练也只是推得快一点。母语者并不逐句判断：流利的产出很大一部分是成块调出的固定说法（Pawley & Syder、Wray 的程式化语言研究），学术写作尤其如此，每一节、每一种写作动作都有一批固定说法。所以第一章练的是“场合 → 说法”的直接联想。

**一题是什么**（`engine/drill.js`）：一行情境，一句话，动词那里空着，下面是两三个现成的说法（*added* / *have added*）。选项由机器从同一小句换不同的时间说出来，一致都配好。

- 选对：自动进入下一题（约 0.6 秒），一题几秒。
- 选错：标出对的那个，给出本题写好的理由，再用一行写出时间背后的三个答案（“这里：一次具体的事 · 现在 · 已经做完，结果还在”），等玩家按“下一题”。三个问题只在这里出现，作解释，不作步骤。
- 错的题过三题再出现，一轮里每题都答对过一次才算完；第一次就答错的题存进存档，下一轮排在最前面。分数是第一次就答错的题数，★ 是全对。
- 桌面上数字键选，回车下一题。

**一关是一个写作场合**（回复审稿人、方法与经过、结论与定理……），同一关的题共享一种说法，过关点题列出这个场合的句式（*We have added / fixed / revised …*）。场合的分组本身就是要记住的东西。

**诚实的边界**：快练只能让每次练习更便宜、更接近要写的东西，省不掉练习的量。跨天的间隔重复还没有做：现在只有一轮之内的重现和下一轮的错题优先。写自己的论文时，改稿阶段专门过一遍时间，是快练之外的另一半。

### 2.2 投稿：可以一直玩下去的模式

快练的题是手写的，玩几轮就背下来了。投稿模式（`kind: 'run'`，`engine/run.js`、`ui/Run.jsx`）把同一批场合放进一条每次都重新生成的路线，用来反复练。借的是肉鸽游戏的结构（每局不同、路线有取舍、一路积累），名字全用投稿和审稿自己的说法：

| 投稿里的东西 | 是什么 | 为什么这样设计 |
|---|---|---|
| 一次投稿 | 一局：从第一轮审稿意见走到程序委员会，七排站点 | 一局十分钟左右，失败就再投一次 |
| 可信度 | 生命值。说错一条意见扣掉它的分量，归零就被拒稿 | 让选错有分量，但不打断练习本身 |
| 句式本 | 手里能用的说法（时间），开局三种（*-ed*、*will*、*have + -en*） | 说法就是要练的东西；选项只从句式本里来，按语法顺序排好，数字键固定 |
| 审稿意见 | 普通的一站，三条意见 | 每条就是一道快练题 |
| 二号审稿人 | 四条意见，至少两条是“看起来像、其实不是”的情境（模板标 `twist`），扣得更重 | 易混的情境集中出现 |
| 改稿夜 | 二选一：休息（可信度 +4），或改稿（重做答错过的意见，每答对一条 +1，答错不扣） | 复习有奖励，取舍是真的 |
| 收进句式本 | 每过一站审稿意见，从三种新说法里收一种，或者不要、恢复 2 点可信度 | 新说法让后面能出的情境更多、选项更多，也更难 |
| 熟练 | 一种说法用对三次即熟练，之后每用对一次恢复 1 点可信度 | 奖励用对，而不是奖励数值配合 |
| 程序委员会 | 最后一站，六条意见，扣得重 | 一局的总结 |

**不重复靠生成，不靠题库。** 意见从情境模板里抽：一个模板是一种场合、一种说法，下面有几份填充（补实验、改笔误、重写证明……）。每次投稿随机生成路线和意见，只出玩家手里有对应说法的情境；同一局里不重复，除非题不够。

**间隔重复藏在随机里。** 每个情境答错一次，存档里的记录 +1，答对一次 −1。抽意见时权重是 1 + 2 × 记录（本局答错过的再 +2），改稿夜也优先挑这些。玩家看到的是随机遇到的意见，实际上是按错题调度的复习。

**游戏层保持薄。** 战斗没有数值配合：一条意见只有对和错，核心动作始终是“读情境 → 选说法”，几秒一次。可信度、熟练、改稿夜只决定这一局能走多远，不改变什么是对的。

**检查**：`npm run check` 把每个模板的每份填充，用这一局可能拿到的每种说法都说一遍，要求读起来互不相同（比如 *read* 的过去式和现在时同形，就不能用在复数主语的模板里）；每条理由对应的说法都必须拿得到。

**还没做**：跨天的间隔（现在的记录只看对错次数，不看时间）；遗物式的被动能力；随难度递增的投稿（更少可信度、更多二号审稿人、限时）。

### 2.3 搭句子：情境 + 语义图

关卡给情境和语义图，玩家把时间、名词短语、动词放进按语序排好的位置，机器说出句子。

| 《图灵完备》 | 句法之图 |
|---|---|
| 真值表 / 测试 | 情境 + 语义图：谓词、参与者及其角色；时间不写出来，要从情境里判断 |
| 元件 | 母语者的选择：时间（这一种关的第一步），以后是主语、限定、语序…… |
| 电路板 | 按语序排好的一排位置：主语，谓语里的时间、动词、动词要的宾语 |
| 门数 / 延迟 | 词数（★ 目标），以后还有歧义解析数 |

**三层，各管一件事：**

1. **机器配形式**（`engine/grammar.js` 的 `inflect`、`said`）：时间加主语得出助动词和动词形式（*has / have*、*is / are*、*was / were*、*-s / ∅*），代词按位置取主格或宾格。快练的选项也是这样说出来的。
2. **放词只拒绝结构错误**（`refuse`）：词放错类的位置、动词没开这个位置。一致和格不会错，所以不拒绝。
3. **运行时比对意思**（`engine/sentence.js` 的 `check`）：读回语义，与语义图逐项比对。时间选错时标出错在三个问题里的哪一问（`timeStep`），并给出关卡的理由。

**时间先定，其余锁住。** 时间没放之前，其余位置锁着。完整的顺序不强制：说话是边想边说的，主语常常比动词先想好。时间放好后，空着的动词位置写出它在等的形式。

**过关后给最小对比。** 通关窗口把同一句话换成本关提供的每一种别的时间说出来，并写出它代表的答案。

**代词通过上下文指称。** 关卡的 `refer` 写明在这一关的语境里 *we*、*they* 指谁。

## 3. 交互：词序条

句子用 kit 的**词序条**（`games/kit/strip`）搭，不用电路：小句只有四五个位置，电路的数据流方向又和语序相反。

- 一排按语序排好的位置，下面用括号标出成分；
- 点一个词，它进建议的空位或第一个能放它的空位；先点位置再点词，就放进那个位置；点已放的词把它拿掉；
- 选了动词，它要的宾语位置就接在它后面（*V NP NP* 开两个，*V NP to NP* 开一个再加 *to*）；
- 位置里显示的就是句子本身。

桌面和手机是同一套交互。

  levels/run.js        投稿：情境模板、开局和可收的说法、站点

引擎在 `games/kit/domains/syntax`，对任何这类游戏都一样：

```

engine/parts.js     词的家族（颜色）和说明
engine/course.js    规格 → 关卡、游玩顺序、课程审计（syntaxCourse）
ui/                 快练页（Drill.jsx）；投稿页（Run.jsx）；搭句子页（情境、语义图、词序条、词块、句子）；地图插图（排字手托，games/stick）
game.jsx            defineSyntaxGame：规格 → 外壳要的游戏描述
validate.js         npm run check：快练的每一题；搭句子关的参考答案、陷阱，以及每个错误时间都有理由
syntax.test.js      npm test：机器配的形式、放词规则、读句子、语义比对
```

## 5. 一关怎么写

**快练关：**

```js
{
  id, kind: 'drill', title, brief, intro?, hint?,
  move: { zh, en },                                    // 写作场合：这一关的题共享它
  items: [{
    context: { zh, en },                               // 一行情境
    words: { SUBJ, V, OBJ?, … },                       // 不带时间的小句，词库里的键
    answer: 'present.perfect',                         // 这里要的时间
    why: { 'past.simple': { zh, en }, … },             // 每个别的选项和它的理由；选项就是 answer 加这些键
  }],
  debrief: { title, body, note },                      // body 写出这个场合的句式
}
```

`npm run check` 检查每一题：词在词库里、语法放得下、至少有一个别的选项、选项说出来互不相同。课程审计只把题目里的时间算作这一关带来的东西：一种新的说法（完成、进行）出现的那一关就是它的引入关。

**写题的纪律：** 情境只给判断所需的事实（在哪写、接着什么、现在的状况），不复述目标句，英语那一面不写出目标时态（不写“the ablation has been added”）。理由一两句，只讲这个场合里母语者为什么不这么说，不讲语法名词。一个场合里两种说法都通的题不要。

**搭句子关：**

```js
{
  id, title, brief, intro?, hint?,
  context: [{ zh, en }],                               // 情境：在哪说、接着什么说、读者知道什么
  meaning: { pred, tense, aspect, roles: { AGENT: { ent, number, label, note? }, … } },
  palette: { time: [...], np: [...], verb: [...] },    // time：本关权衡的时间（'present.perfect'），决定打开哪些答案；词：包括干扰项
  why: { <time key>: { zh, en } },                     // 每个错误时间的理由：母语者为什么在这里不这么说
  preset?: { SUBJ, V, … },                             // 已经放好、拿不掉的位置
  refer?: { we: 'author', … },                         // 代词在本关语境里指谁
  target?: 8,                                          // ★ 的词数上限
  answer: { SUBJ, TIME, V, OBJ?, IOBJ?, TO? },          // 参考答案，按位置写词库里的键
  traps: [{ answer, fails: 'grammar' | 'pred' | 'time' | 'role' | 'star' }],
  debrief: { title, body, note },
}
```

**情境不泄题。** 不复述目标句，不用问题选项里的词（结果、正在、一直），英语那一面不写出目标时态。语义图已经给出要说的事，情境只给判断所需的事实：在哪说、接着什么、现在的状况。

**情境要让答案唯一。** 一个情境里，两种时间都说得通的话，这一关就不成立；写情境时先写出每个错误选项的理由，写不出来，说明情境还不够确定。理由只讲这个情境里的判断，不讲语法名词。

**陷阱是规格的一部分。** 每一关都写出玩家最可能试的错句，并写明它在哪一层被拦下。

**一关一个新想法**（课程审计）：概念按母语者的决定划分。所有名词短语和动词算一个概念（“放词”）；每种视角（一般、完成、进行）各算一个，同一视角的不同时间是它的型号。

| 关 | 场合 | 新说法 | 题数 | 选项 |
|---|---|---|---|---|

| 1-3 方法与经过 | 方法、设置、数据 | 练习：换方向 | 7 | 过去 / 完成，含一道周报（完成） |
| 1-4 结论与定理 | 结果、结论、相关工作 | 一般现在（论文的两只钟） | 7 | 现在 / 过去 / 完成 |
| 1-5 正在进行 | 近况与经过 | 进行（be + -ing） | 6 | 进行 / 一般 / 完成 |
| 1-6 那时之前 | 讲一段经过 | 过去完成（had + 过去分词） | 5 | 过去完成 / 过去 / 现在完成，含一道按顺序讲（过去） |
| 1-7 一封回复信 | 回复信从头到尾 | 组合：五种说法混在一封信里 | 6 | 每题三选一 |

每关都混进几道“看起来像这一关、其实不是”的题（回复信里被问到“什么时候”，方法一节里的周报），免得玩家只记“这一关都选同一个”。

存档第 5 版把第一章换成快练：关卡全部是新的，进度和草稿都不带过来。更早的版本（第 2–4 版）是搭句子版本的几次重排和改名。

| 3 读者认得出吗 | a / the / 复数 / 不加，由读者能否认出决定 | 语义图标出读者已知的实体；限定词由玩家按“认不认得出”选，形式由机器配 | 第一次提到用 a，上文说过或双方都知道的用 the |
| 4 旧在前，新在后 | 句首接上文，新信息和长成分放句尾 | 情境里写出上一句；词序条允许成分移动（主题化、外置、与格交替） | *send the editor a rebuttal* 还是 *send a rebuttal to the editor*：看哪个是新的、哪个更长 |
| 5 中心词在前 | 先说是什么，修饰放在后面 | 后置修饰：介词短语、定语从句作为可放进名词短语的块 | *the method that we propose in Section 3* |
| 6 主次分明 | 一句一个主干，其余挂成从属成分 | 从句、非谓语；多个语义图合成一句 | 把三件事说成一个主干两个从属，主干放最重要的那件 |
| 7 断言有多强 | 按证据选承诺强度 | 语义图标出证据强度 | *shows* / *suggests* / *may* |
| 8 母语者关卡 | 无歧义、最精简 | 验证器枚举全部合法解析，有歧义即失败 | 悬垂修饰语、平行结构、极限精简 |

## 8. 诚实的限制

- "先定时间"用的是说话产出的模型（Levelt），不是说母语者真的等时间定好才想别的：说话是边想边说的，主语常常比动词先想好。游戏练的是“时间属于意思本身、从一开始就在”这个习惯，界面也只是提示时间先行，不强制顺序。
- 情境里的判断有边界：真实写作中不少地方两种说法都可以（比如有的结论用过去时报告，也被接受）。关卡只收答案唯一的情境，所以练出的是典型判断，不是全部用法。
- 词库是封闭的。这是解谜，不是自由写作；用词的丰富度要靠别的途径。
- 修辞上的“好”超出可量化指标，只能用词数、歧义数这类代价间接体现。
- 第 8 章的“唯一解析”取决于文法的覆盖度：文法漏掉的歧义，验证器也查不出来。
- 显性的知识向流利使用的迁移有限。这个游戏能让人在写作时问对问题，但语感的主体仍靠大量阅读。
