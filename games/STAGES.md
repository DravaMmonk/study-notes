# 管线分段与缩略视图：开发文档

给接手实现的会话。先读本文，再读 `games/DESIGN.md` 第 6.9 节（元件定义、三面视图）、第 6.10 节（界面，特别是「值怎么显示：数据形状 × 显示方式 × 场景」）和 `games/vision-lab/DESIGN.md` 里关于升级系列（assembly upgrade series）的部分。

## 1. 问题

元件从「搭出封装件、下一关当一个元件用」改成了「在同一块电路上原地升级」（升级系列：每次升级从上一次通过的电路开始，直接改里面的元件，`kit/engine/assembly-series.js`）。好处是整条管线一直摆在玩家面前、能改；代价是到后几关电路很大：《视觉实验室》第 1 章末的扫描仪有十几个元件，线交叉穿过整块板，读数矩阵把卡片撑大，手机上是一长串格位。

目标：**既展示管线全貌，又不凌乱**。

## 2. 已经定下的设计

这些和用户逐条确认过，实现时不再改方向；细节有疑问写在第 8 节。

1. **电路结构和画面结构分开。** 电路仍是一块平的板，升级在板上原地做。画面上加一层**分段**（stage）：一段 = 某一关（某一次升级）留下的那一组元件。分段**只是看法**：不是元件、不进元件箱、不进蓝图文本、不进存档、不影响运行和判定。
2. **分段从课程自动推出，玩家不能自建分组**（先这样）。
3. **桌面**：每段可以折叠、展开。
   - 折叠态是一张**缩略示意图**：段里的元件按数据流排成小图，每个元件只写名字和一行（由元件的第四面 `mini` 决定，见 5），线照画；段对外的口在边框上，外面的线接在这里；出口旁一个这段输出的缩略图（views 的 `card` 场景）。
   - 展开态是元件原样摆在板上，外面套一个带段名的淡色框。
   - 默认：以前各关留下的段折叠，这一关新放的元件不归段、照常显示。
   - 折叠态只读；指向缩略里的一个元件弹出它的名字和当前值（views `detail` 场景）；点它展开这一段并选中它；单步运行走到段里时，缩略里对应的元件高亮。
4. **手机**：手风琴，同一时间只展开一段。折叠的段占一整行：段名、名字链（「翻转核 → 展开邻域 → 四则运算 → …」）、出口的缩略图。点开就地展开成格位，其他段收起。段与段之间只画一个向下的箭头；单步运行时自动展开当前步所在的段并滚到眼前。
5. **元件的第四面 `mini`**（parts.json `views.mini`）：分段折叠后示意图里这个元件的样子。版式由 kit 固定：名字一行，下面最多一行，块之间用「·」连，超长截断不换行，只读。能用的块只有 `summary`、`setting`（只能 `as: 'label'`）、`text`、`value`（按 views 的 `inline` 场景画，一行高）。不写时的默认：名字 + 各设置的值的字（如「四则运算 · ×」「展开邻域 · 横向 · 延续边缘」）。studio 的元件编辑器加第四栏编辑它，和 `card`、`tile`、`detail` 三栏同一种编辑方式。
6. **跨段的连接改成标签**：一个源接到别的段、或者线很长时，不画贯穿全板的线，两端各画一个短桩写上源的名字，点一下高亮并跳到另一端（手机上跳到并展开另一端所在的段）。段内的线照画。
7. **自动排版**：按数据流从左到右分列；段内也按依赖排；段与段之间的线成束。保留一个「整理」，玩家挪乱了能一键排回。
8. **审计**：一个任务打开时不折叠的元件（即这一关新放的，参考解里的）超过上限（先定 8）就报出来，提示拆关或者先搭出一个中间段。这是从内容上兜住手机能承受的复杂度。

## 4. 分段的数据

新模块 `kit/engine/stages.js`（node 下能跑，不碰界面），配单元测试 `stages.test.js`。

```
stagesOf({ task, board, chain }) → { stages: [{ id, label, nodes: [node id], ins: [wire], outs: [wire] }], loose: [node id] }
```

- `chain`：这个任务打开时那块板的来历，从最早到最近：`[{ id, label, board }]`。每一项是升级链（或 `carry` 链）上的一关：它的板取玩家在那一关通过时留下的（`progress.built`），没有就取那一关的参考解。底座已经有找这条链要的东西（`circuit.opening`、`carries`、升级系列的 `resolve`），在 `circuit-domain.js` 里加一个 `stageChain(task, built)` 给出它。
- 归属规则：板上一个元件，在链上第一次出现于哪一关的板里（按 id），就属于那一段；链上都没有的属于这一关（`loose`，不归段）。关卡给的固定卡片（输入、输出）不归段。
- `ins` / `outs`：一端在段里、另一端在段外的线，就是这段对外的口。
- 段名 `label`：任务可以写一个可选字段 `stage`（`S.opt(S.text())`，section `read`），说它这一步搭出的是什么（「求梯度」）；不写就用那一关的标题。字段加在 `levelSchema` 的任务上（`circuit-domain.js`），各底座领域的词汇表版本照例重印（第 7 节）。
- 玩家删掉再重放的元件是新 id，算这一关的，属预期行为。

单元测试（不读任何一款游戏的关卡，测试里现写小内容）：三关的升级链分出三段；在后一关改了前一段元件的设置，它仍在原来的段；新放的元件归 `loose`；跨段的线落在对的 `ins` / `outs`；没有来历的任务没有段。

## 5. 分步实施

每一步一次提交，直接推到 main（先 `git pull --rebase`，另一个会话也在推）。每步都跑第 7 节的验证。

### 第 1 步：分段数据

- `kit/engine/stages.js` + 测试；`circuit-domain.js` 的 `stageChain`；任务字段 `stage`。
- `CircuitScreen.jsx` 算出当前板的分段，交给 `CircuitLevel`（先不画，下一步用）。
- 验收：单元测试过；`npm run check` 全过；在《视觉实验室》第 1 章末几关的参考解上，打印出的分段和关卡对得上（在报告里列出来）。

### 第 2 步：元件第四面 `mini`

- `engine/parts/schema.js`：`FACES` 加 `mini`；`views.mini` 只允许受限的块（`summary`、`setting` 且 `as: 'label'`、`text`、`value`），用单独的 schema 表达，不靠运行时判断。
- 默认规则（不写时）：名字 + 各设置的值的字，用「·」连。由 kit 给，搭出的封装件只写名字，固定卡片不在缩略里画成元件（是段的口）。
- 渲染：`shell/parts/` 里加 `mini` 的画法；`value` 块经 `kit/views/Show.jsx` 的 `inline` 场景。代码里定义元件（不是 parts.json）的领域，缩略面一律用默认规则。
- studio：`PartFields.jsx` / `PartPreview.jsx` 加第四栏「缩略」，预览是把这个元件单独放进一个折叠段示意图（两边虚线的上下游），改了立即看到。
- DESIGN 第 6.9 节的「三面视图」改成四面，块表注明哪些块能用在 `mini`。
- 验收：schema 拒绝在 `mini` 里放控件、按钮、口、领域显示项；studio 里给一个元件改 `mini` 经操作集落盘、预览随之变化（浏览器里走一遍，截图）。

### 第 3 步：桌面的折叠和展开

- 把 `svg.js` 的分列排版抽成共用的 `kit/circuit/layout.js`（`svg.js` 改用它，studio 和 MCP 的输出不变：`svg.test.js` 照旧过），桌面折叠态和第 7 步的「整理」都用它。缩略示意图画元件时用 `mini` 面，不写蓝图类型名。
- `CanvasEditor.jsx`：一段折叠时，它的元件不画，换成一张示意图卡放在这些元件原来所占区域的左上；进出这段的线改接到卡边的口上；出口旁一个 views `card` 场景的缩略图。展开时元件原样画，外面一个带段名的淡色框（样式参考框的区域底色，颜色取 tokens）。
- 折叠和展开的状态只在界面里（不进存档）；默认以前的段折叠。
- 交互：指向缩略里的元件弹出名字和值；点它展开并选中；单步高亮缩略里的元件（`trace` 里的节点 id 落在哪段，就点亮那段缩略里的它）。
- 判定、运行、蓝图文本、存档与折叠无关：加测试或在报告里说明怎么确认的。
- 验收：《视觉实验室》第 1 章最后一关打开时，板上是「几张段的示意图 + 本关新增的元件」；展开一段改一个设置能跑通；截图（浅色、深色主题各一）。

### 第 4 步：手机手风琴

- `SlotBoard.jsx`：段占一整行（段名、名字链、出口缩略图），点开就地展开成格位（框在手机上已是子格位，复用那套行对齐），同时只有一段展开；段间一个向下的箭头。
- 单步时自动展开当前步所在的段并滚到眼前。
- 验收：iPhone 13 视口下同一关的截图；同一时间只有一段展开；跑一遍测试不出错。

### 第 5 步：跨段连接改成标签

- 规则由 kit 定：线的两端不在同一段（或一端在段里、一端是这一关新放的元件，且跨过了别的段），或者一个源扇出到两段以上时，画成两端的标签；其余照画。阈值写在一处，DESIGN 里写明。
- 点一端的标签：高亮配对的另一端，必要时展开它所在的段并滚过去。
- 桌面和手机共用这条规则。
- 验收：第 1 章最后一关的截图里没有贯穿全板的长线；标签能来回跳。

### 第 6 步：审计「打开时不折叠的元件数」

- `kit/course.js` 加一条规则（名字如 `open-crowded`）：一个任务的参考解里不属于任何段的元件超过 8 个就报。只在有段的任务上查。
- 先在所有游戏上跑一遍，列出报出来的任务，在报告里给出来；不改关卡内容（关卡是否拆由用户定），必要时先写进对应游戏 `game.json` 的 `open`。

### 第 7 步：自动排版和「整理」

- 「整理」按数据流重排整块板（段作为整体参与排版），可以撤销。
- 新放进来的元件仍按现在的方式落位，不自动挪动玩家摆好的东西。

## 8. 留给实现时确认的

- 折叠态示意图太大（段里元件很多）时：先按比例缩，缩到字读不清（比如低于 9px）就退成一行名字链。具体阈值实现时看效果定，写进 DESIGN。
- 展开一段时，其余段是否保持折叠（桌面允许同时展开几段，手机只一段）——按第 2 节，桌面允许多段。
- 一个元件在后一关被删掉、又在更后一关以新 id 重放：它算重放那一关的。若这让分段明显不对，报告给用户再定。
- 若推导分段时发现升级链上某一关的板拿不到（既没有玩家的板也没有参考解），这一关的元件归 `loose`，并在报告里说明。
