# 管线分段与缩略视图：开发文档

给接手实现的会话。先读本文，再读 `games/DESIGN.md` 第 6.9 节（元件定义、三面视图）、第 6.10 节（界面，特别是「值怎么显示：数据形状 × 显示方式 × 场景」）和 `games/vision-lab/DESIGN.md` 里关于升级系列（assembly upgrade series）的部分。

## 1. 问题

元件从「搭出封装件、下一关当一个元件用」改成了「在同一块电路上原地升级」（升级系列：每次升级从上一次通过的电路开始，直接改里面的元件，`kit/engine/assembly-series.js`）。好处是整条管线一直摆在玩家面前、能改；代价是到后几关电路很大：《视觉实验室》第 1 章末的扫描仪有十几个元件，线交叉穿过整块板，读数矩阵把卡片撑大，手机上是一长串格位。

目标：**既展示管线全貌，又不凌乱**。

## 2. 已经定下的设计

这些和用户逐条确认过，实现时不再改方向；细节有疑问写在第 8 节。

1. **电路结构和画面结构分开。** 电路仍是一块平的板，升级在板上原地做。画面上加一层**分段**（stage）：一段 = 某一关（某一次升级）留下的那一组元件。分段**只是看法**：不是元件、不进元件箱、不进蓝图文本、不进存档、不影响运行和判定。
2. **分段从课程自动推出**，作为预设；手机上玩家可以用分割线自己分、写批注（第 9 节修订）。
3. **桌面**：每段可以折叠、展开。
   - 折叠态是一张**缩略示意图**：段里的元件按数据流排成小图，每个元件只写名字和一行（由元件的第四面 `mini` 决定，见 5），线照画；段对外的口在边框上，外面的线接在这里；出口旁一个这段输出的缩略图（views 的 `card` 场景）。
   - 展开态是元件原样摆在板上，外面套一个带段名的淡色框。
   - 默认：以前各关留下的段折叠，这一关新放的元件不归段、照常显示。
   - 折叠态只读；指向缩略里的一个元件弹出它的名字和当前值（views `detail` 场景）；点它展开这一段并选中它；单步运行走到段里时，缩略里对应的元件高亮。
4. **手机**：~~手风琴~~ 已由第 9 节的分割线替换。原写法：手风琴，同一时间只展开一段。折叠的段占一整行：段名、名字链（「翻转核 → 展开邻域 → 四则运算 → …」）、出口的缩略图。点开就地展开成格位，其他段收起。段与段之间只画一个向下的箭头；单步运行时自动展开当前步所在的段并滚到眼前。
5. **元件的第四面 `mini`**（parts.json `views.mini`）：分段折叠后示意图里这个元件的样子。版式由 kit 固定：名字一行，下面最多一行，块之间用「·」连，超长截断不换行，只读。能用的块只有 `summary`、`setting`（只能 `as: 'label'`）、`text`、`value`（按 views 的 `inline` 场景画，一行高）。不写时的默认：名字 + 各设置的值的字（如「四则运算 · ×」「展开邻域 · 横向 · 延续边缘」）。studio 的元件编辑器加第四栏编辑它，和 `card`、`tile`、`detail` 三栏同一种编辑方式。
6. **跨段的连接改成标签**：一个源接到别的段、或者线很长时，不画贯穿全板的线，两端各画一个短桩写上源的名字，点一下高亮并跳到另一端（手机上跳到并展开另一端所在的段）。段内的线照画。
7. **自动排版**：按数据流从左到右分列；段内也按依赖排；段与段之间的线成束。保留一个「整理」，玩家挪乱了能一键排回。
8. **审计**：一个任务打开时不折叠的元件（即这一关新放的，参考解里的）超过上限（先定 8）就报出来，提示拆关或者先搭出一个中间段。这是从内容上兜住手机能承受的复杂度。

## 4. 分段的数据

新模块 `kit/engine/stages.js`（node 下能跑，不碰界面），配单元测试 `stages.test.js`。

```
stagesOf({ task, board, chain }) → { stages: [{ id, label, nodes: [node id], ins: [wire], outs: [wire] }], loose: [node id] }
```

- `chain`：这个任务打开时那块板的来历，从最早到最近：`[{ id, label, board }]`。每一项是升级链（或 `carry` 链）上的一关：它的板取玩家在那一关通过时留下的（`progress.built`），没有就取那一关的参考解。底座已经有找这条链要的东西（`circuit.opening`、`carries`、升级系列的 `resolve`），在 `circuit-domain.js` 里加一个 `stageChain(task, built)` 给出它。
- 归属规则：板上一个元件，在链上第一次出现于哪一关的板里（按 id），就属于那一段；链上都没有的属于这一关（`loose`，不归段）。关卡给的固定卡片（输入、输出）不归段。
- `ins` / `outs`：一端在段里、另一端在段外的线，就是这段对外的口。
- 段名 `label`：任务可以写一个可选字段 `stage`（`S.opt(S.text())`，section `read`），说它这一步搭出的是什么（「求梯度」）；不写就用那一关的标题。字段加在 `levelSchema` 的任务上（`circuit-domain.js`），各底座领域的词汇表版本照例重印（第 7 节）。
- 玩家删掉再重放的元件是新 id，算这一关的，属预期行为。

单元测试（不读任何一款游戏的关卡，测试里现写小内容）：三关的升级链分出三段；在后一关改了前一段元件的设置，它仍在原来的段；新放的元件归 `loose`；跨段的线落在对的 `ins` / `outs`；没有来历的任务没有段。

## 9. 修订：手机改用折叠视图和分割线（替换第 4 步的手风琴）

第 1–6 步已经做完（`ec325f1` … `f380741`）。手机上的手风琴做出来后，段成了另一套和格位不一样的卡片（整行的段卡、名字链、大块读数），上面元件的线还贯穿这些段卡。用户改成下面的做法：**不另做卡片，就在原来的格位板上分段**。手风琴整个拿掉（硬切换，`SlotBoard.jsx`、`circuit.css` 里它的代码和样式都删掉）。

### 9.1 设计

1. **全部折叠（紧凑格位）。** 格位板工具行（「电路 N」、清空、撤销重做、「全部接线」那一行）加一个开关：打开后每个元件只画名字和一行，这一行就是元件的 `mini` 面（第 2 步已有），读数矩阵、设置控件都收起来。格子同时变窄，格位板左侧空出一条窄边（gutter），给分割线的把手和批注用。开关是这台设备上的偏好（`localStorage`，按游戏记），不进存档。点一个紧凑格子仍是现在的单子（详情）。
2. **分割线。** 分割线画在两行格子之间的空隙里（就是现在「+」空格所在行上方、下方那道缝），横跨格位板，左侧窄边里是它的把手。一条分割线到下一条之间的那几行就是一**节**。
   - 分割线上写这一节的**批注**（一句话，可空）；点批注可以改。
   - 分割线左端一个折叠钮：折起这一节时，这几行收成分割线本身（一条细线 + 批注 + 「n 个元件」），不另画卡片；再点展开。
   - 紧凑模式下，两行之间的缝隙里在窄边出现一个淡的「＋」，点它在这里插一条分割线；按住把手上下拖，分割线落到另一道缝；分割线的菜单里能删掉它。
   - 进出一个折起的节的线，端点落在这条分割线上，并按第 5 步的规则画成标签；不再有线穿过折起的节。
3. **预设和玩家的分割线是同一种东西。**
   - 板上还没有分割线时，kit 按分段（`stagesOf`）生成预设：每段的元件排在连续的几行，段与段之间一条分割线，批注是段名（任务的 `stage`，没写就是关卡标题）；以前各关的节默认折起，这一关新放的元件在最下面一节、展开。
   - 玩家一旦动过（加、删、移分割线，改批注，折起或展开），分割线就写进这块板，以后用玩家的。
   - 分段（第 1 步）因此只用来生成预设和审计（第 6 步），画面上的分组一律以分割线为准。
4. **存在哪。** 分割线是排版，和元件的 `slot`、框的 `narrow` 一样存在板上：`board.sections: [{ row, note?, folded? }]`，`row` 是分割线下面那一行的行号（按 `circuit/model.js` 的格位行）。蓝图文本、运行、判定、检查都不读它（和 `x`、`y`、`slot` 一样）。删掉一条分割线不动任何元件。
5. **桌面。** 桌面读同一份分割线：一节就是桌面上的一段（第 3 步的折叠示意图 / 展开的淡色框），段名换成这一节的批注，折起状态也用这一节的 `folded`。节的成员 = 格位落在这几行里的元件（没用过手机的板，格位由 kit 按预设算出来，同样有）。桌面上暂不提供编辑分割线（以后再说），这一点写进 DESIGN。
6. **自动排版。** 第 7 步「整理」在手机上按节重排：每节内按数据流排，节的顺序和分割线不变。

### 9.2 步骤

- **9a 数据和预设**：`board.sections` 的读写（`circuit/model.js`）；没有时由分段生成预设，并把各段的元件排进连续的行（`placeSlots` 那一层）；成员计算 `sectionsOf(board, layout)` 放在 `circuit/` 里，配单元测试（预设的行、玩家移动分割线后成员变化、删除分割线不动元件、蓝图文本不含它）。
- **9b 手机画法**：紧凑开关、窄边、分割线（批注、折叠钮、插入、拖动、删除），折起的节只剩一条线，线的端点落到分割线上。删掉手风琴。
- **9c 桌面改读分割线**：第 3 步的分段改用节；段名用批注；折起状态用 `folded`。
- **9d 文档**：DESIGN 第 6.10 节「管线分段」一段改写（预设 + 玩家分割线 + 批注 + 存在板上），第 5 节审计表不变。

验收：同一关（《视觉实验室》扫描仪那一关）iPhone 13 视口下，紧凑模式截图里没有段卡、没有线穿过折起的节；加一条分割线、写批注、折起、刷新后还在；桌面上同一块板显示同样的分节和批注；全部测试跑通。约定和验证照第 7 节。

## 10. 修订：玩家设置（把手动分段等高级功能放进设置）

用户的决定：手动分段这类高级功能不默认摆在玩家面前，放进一个**设置**里由玩家自己打开。默认体验保持最简单：只有预设的分段，玩家能折起、展开，但看不到加分割线、拖动、改批注这些编辑入口。

### 10.1 设计

1. **入口。** 游戏顶栏（引言、百科、语言、主题那一排）加一个齿轮按钮「设置」。桌面上是按钮旁弹出的框（`kit/shell/Popover.jsx` 的约定），手机上是底部单子。地图页和关卡里都能打开。语言和主题两个菜单是整个笔记站共用的（`kit/menu.js`），不搬进来。
2. **设置是 kit 的登记表，不是各游戏各写一套。** 新模块 `kit/shell/settings.js`：
   - `defineSetting({ key, label, kind: 'toggle' | 'choice', options?, default, when? })` 登记一项；`when(game)` 说这一项在这款游戏里有没有意义，没有意义就不出现在面板里（例如没有分段的游戏不显示「手动分段」）。
   - `useSetting(key)` → `[value, set]`，组件里读写。
   - 存在这台设备上（`localStorage` 一个键，例如 `games.settings`，按游戏分开存：`{ [gameId]: { [key]: value } }`），读写都包 try/catch，读不到就用默认值。不进存档，不影响 `stamp`。
   - 登记只在 kit 里做（随功能一起登记）；内容和领域不能加设置项。以后需要领域登记再开口子。
3. **面板。** 一项一行：名字 + 开关或几个选项按钮，不加说明文字（布局自己说话，DESIGN 第 6.10 节）。按功能分两组，组间一条细线：「显示」「编辑」。最下面一行「恢复默认」。
4. **第一批设置项**（只放已经有、或第 9 节正在做的功能）：

   | 组 | 设置 | 默认 | 打开后 |
   |---|---|---|---|
   | 编辑 | 手动分段 | 关 | 手机紧凑模式下窄边出现「＋」，分割线可拖动、可删除、批注可改（第 9 节第 2 条的编辑入口全部受它控制）；关闭时这些入口都不出现，已有的分割线和批注照常显示、照常能折起展开 |
   | 显示 | 打开关卡时紧凑格位 | 关 | 手机上进关卡时直接是紧凑模式（工具行的开关仍在，随时切换） |
   | 显示 | 跨段连线画成标签 | 开 | 关闭后跨段的线照常画成线（第 5 步的标签规则只在打开时生效） |
   | 显示 | 网格默认显示 | 游戏的默认 | 在这款游戏给网格列的几种显示方式之间选（数值格、图像），和结果区的切换是同一个选择（`kit/views/choice.js`）；游戏只给一种时这一项不出现 |

   「手动分段」打开前玩家自己没改过分割线时，板上是预设；关掉它不删掉玩家已经写进板里的分割线（它们是排版，和元件位置一样）。
5. **以后加设置项的规则**（写进 DESIGN）：只放改变**呈现和编辑方式**的选项，不放改变谜题、判定、提示多少的选项；默认值就是最简单的体验；一项一个短名字。

### 10.2 步骤

- **10a 登记表**：`kit/shell/settings.js` + 单元测试（默认值、按游戏分开、读写失败回到默认、`when` 过滤）。`kit/views/choice.js` 的选择也经它存，同一个键里（硬切换，删掉 choice.js 自己的存取）。
- **10b 面板**：顶栏齿轮按钮，桌面弹框、手机单子；按 `when` 列出这款游戏有意义的设置。
- **10c 接上**：第 9 节的分割线编辑入口受「手动分段」控制；紧凑格位的初始状态；标签规则的开关；网格默认显示。
- **10d 文档**：DESIGN 第 6.10 节加「玩家设置」一段（入口、登记表、存哪、加设置项的规则）。

验收：默认状态下手机上看不到任何分割线编辑入口；打开「手动分段」后能加、拖、删分割线和改批注，关掉后入口消失、分割线还在；换一款没有分段的游戏，面板里没有这一项；刷新页面设置还在；桌面和手机截图（浅色、深色）。约定和验证照第 7 节。
