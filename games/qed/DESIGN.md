# 《证明完毕》（形式化验证）设计框架

《证明完毕》（Q.E.D.，id `qed`），专题是形式化验证：从逻辑推理到程序正确性证明。所有类图灵完备游戏共同遵守的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；本文档只记录这个专题自己的内容。

**现状：** 第 0–2 代的 demo 已经做出来（27 关：真值表 3 关，初号 11 关含演绎定理专题和一个挑战，二号 13 关含骑士与无赖专题和一个挑战），规格在 `spec.js` 和 `levels/`，界面和规则都在 `kit/domains/logic`。第 3 代起只有本文档里的框架。

**终点：** 学完以后，学习者拿到一段小程序，能自己写出它的规格、找到循环不变式，并在游戏的证明核里证完；看到一个"显然成立"的命题，会先找反例，找不到再找证明。

## 1. 映射：把《图灵完备》搬到证明上

| 《图灵完备》 / 已有两款 | 证明完毕 |
|---|---|
| 原件 NAND | 第 1 代只有一条规则（分离规则 MP）和两条公理模式（K、S）。和 NAND 一样，它们够用，但用起来很费劲，这份费劲就是后面几代存在的理由 |
| 线上传的值 | 线上传的是**命题**：一根线代表"这个命题已经被证出来了"。元件是推理规则，输入口是前提，输出口是结论 |
| 字母 | 元件是模式，它的名字、说明和端口可以用字母（分离的两个口是「A → B」和「A」）。玩家能操作的内容（已知、目标、卡片上选的句子）都是日常句子；要玩家自己写抽象公式，留到很后期、各种证明机制都已用熟的章节 |
| 输入卡片 / 输出卡片 | 输入卡片是假设和公理（点一条加一个输出口，和《状态之图》一样）；输出卡片是要证的目标 |
| 测试 + 反例 | 目标本身就是规格。接错时指出第一处对不上的口，并排显示"这里要的"和"接进来的"（对应《状态之图》的第一格算错）。目标本身是假的时，给出**反模型**：一行真值表、一个 2–3 个元素的小世界、一组让程序出错的输入 |
| 搭好的电路变成元件 | 证出来的**引理**变成一条新规则，后面直接用。黑盒和"搭出它的那一关"必然一致：引理的陈述就是那一关的目标，那一关的证明已经过了核检查 |
| 元件数 / 计算量评分 | 证明步数（规则应用次数）。约束挑战靠它 |
| 故意犯错关 | 让学习者去证一个假命题，亲眼看反模型；或者在"任取"框里偷用了假设里的变量，看它推出荒谬的结论 |
| 机体 | 证明机。每一代多一种推理能力：假设框、量词、归纳、程序、状态空间 |

**要练出的思维：** 先找反例再找证明、把目标拆成子目标、从结论倒推、引理与复用、加强归纳假设、设计不变式、规格够不够强。

## 2. 核心机制

1. **证明板（主机制，复用 kit 的电路编辑器）。** 元件是带**模式变量**的规则，比如 MP 是"输入 A→B 和 A，输出 B"。接上线时引擎做合一，把 A、B 定下来，线上立刻显示具体的命题。证明通过的条件：每个元件的口都对得上，输出卡片和目标一致，没有用到框外不该用的假设。
2. **框（新 kit 能力：嵌套子板）。** 引入"假设"的规则是一个带内板的元件。→引入：内板多一张输入卡片 A，内板的输出卡片接到 B，外面这个元件就输出 A→B。分情况、任取、取出见证、归纳都是这种元件（归纳有两块内板：起点和一步，"一步"的内板多一张归纳假设卡片）。手机上框是一个格位，点进去是它自己的电路板。
3. **反模型面板（对应测试面板）。** 随时对当前目标和每个框的目标跑一次语义检查：命题逻辑穷举真值表；一阶逻辑在 2–3 个元素的小世界里搜；算术和程序在关卡声明的小范围内枚举。找到就画出来，并告诉学习者"这个目标证不出来"。
4. **写法切换（对应《视觉完备》的画法）。** 同一个命题可以显示成符号（A → B）、文字（若 A 则 B）、树。第 5 代起，程序有"代码"和"流程图"两种画法。
5. **通关点题附原生写法。** 过关后点题，同时给出同一个证明在 Isabelle/Isar 里大致怎么写，让学习者知道游戏外的工具长什么样。只是展示，不要求学习者写。

### 第 0 代 · 纸笔

还没有证明机。一个命题是一张真值表，"永远成立"就是每一行都是真。

| 关 | 名称 | 新东西 |
|---|---|---|
| 0-1 | 真值表 | 手填 A→B 的真值表 |
| 0-2 | 永远成立 | 判断几个命题是不是每一行都真 |
| 0-3 | 只要一行 | 找出让 (A→B)→A 为假的那一行：反例只要一个 |

0-3 的结尾点明：真值表在变量多了以后会爆炸（n 个变量 2ⁿ 行），而且到了"对所有的数"就根本列不完。所以需要证明。

### 第 1 代 · 初号（希尔伯特系统）

**能力：** 只有一条规则 MP，和公理 K：A→(B→A)、S：(A→(B→C))→((A→B)→(A→C))。公理是元件，放下时 A、B、C 由接上的线决定。这一代刻意做得窄而短，让学习者体会到"什么都能证，但很累"。

**地基**

| 关 | 名称 | 新东西 | 产出 |
|---|---|---|---|
| 1-1 | 照抄 | 证明板；假设卡片直接接到目标 | — |
| 1-2 | 分离 | MP | — |
| 1-3 | 凭空成立 | 公理 K：没有假设也能证出东西 | — |
| 1-4 | 自己推出自己 | 公理 S；证 A→A（要 5 步） | **恒等** |
| 1-5 | 接起来 | 由 A→B、B→C 证 A→C | **串联** |

**练习（按难度）：** 交换前提 (A→B→C)→(B→A→C)、丢掉多余的前提、两次用同一个前提 (A→A→B)→(A→B)。

**专题：演绎定理。** 终极谜题：给出一个"在假设 A 下证出 B"的证明，把它改写成不用假设的 A→B 的证明。倒推出三种情况，正好是演绎定理证明的三个归纳情形：

| 关 | 加回的机制 |
|---|---|
| D1 假设就是 A | 这一步用的正是 A：换成恒等 |
| D2 和 A 无关 | 这一步是公理或别的假设：用 K 包一层 |
| D3 这一步是 MP | 两边都已改写好：用 S 合起来 |
| D4 改写整个证明（终极） | 一个 4 步的证明，逐步套用上面三种 |

**挑战：** 最短的恒等（约束挑战：A→A 不超过 5 步，要求代价度量；naive 解先证一个更一般的引理再实例化，超出预算）。

**到下一代：** 二号的引言说："上一代你亲手证明了：只要能在假设 A 下推出 B，就能得到 A→B。二号把这件事做成了身体的一部分。" 假设框就是演绎定理。

### 第 2 代 · 二号（自然演绎，命题逻辑）

**能力：** 假设框（→引入）、分情况（∨消去，两块内板）。每个连接词的引入、消去规则作为原始元件，一关出现一个。二号一开始是直觉主义的：没有反证法。元件跟着机体走：二号只带上分离（→消去），K、S 和用它们证出的串联、恒等都留在初号。

**地基：** 2-1 打开一个框（→引入）、2-2 两个都要（∧引入 / ∧消去）、2-3 二选一（∨引入）、2-4 分情况（∨消去）、2-5 矛盾（⊥ 和"¬A 就是 A→⊥"）。

**练习（并行组：[合取与析取：交换律、分配律 ∥ 否定：逆否、三条直觉主义可证的德摩根律]）**，最后是 2-x 反证法：¬¬A→A 作为新的原始元件出现，之后能证排中律。

**专题：骑士与无赖。** 世界：岛上的人要么永远说真话（骑士），要么永远说假话（无赖）；每个人说的话成为一张输入卡片"a 是骑士 ↔ a 说的话"。

| 关 | 加回的机制 | 产出 |
|---|---|---|
| K1 一个岛民 | 一句话、一个人：拆开 ↔ | **拆双向**（↔ 的两个方向） |
| K2 两个岛民 | 分情况：假设 a 是骑士，推出矛盾 | — |
| K3 三个岛民 | 嵌套的分情况，矛盾排除掉的情况 | — |
| K4 五个岛民（终极） | 完整的谜题；要先想清楚从谁下手 | — |

**挑战：** 在反证法出现之前证 ¬¬(A∨¬A)（naive 解：直接证 A∨¬A，卡住；跳跃：先假设 ¬(A∨¬A)，再两次用它）；皮尔士律 ((A→B)→A)→A（只在反证法之后开）。

### 第 3 代 · 三号（一阶逻辑）

**能力：** 任取框（∀引入：内板多一张"新变量 x"卡片，引擎检查 x 不出现在框外的假设里）、实例化（∀消去，接一个项）、见证（∃引入）、取出见证（∃消去，带内板）、相等（自反、代换）。

**地基：** 3-1 对所有、3-2 取一个、3-3 存在一个、3-4 拿出那一个、3-5 相等就能换。

**故意犯错：** 3-6 偷换变量。关卡让学习者去证 (∀x.∃y.R(y,x)) → (∃y.∀x.R(y,x)) 这种量词换了顺序的假命题；直觉的做法会在任取框里用到框外的变量，被拦下时，反模型面板在一个两元素的世界里画出为什么不成立。

**练习：** 量词交换（∃∀ → ∀∃ 能证）、族谱（父母、祖先的公理，证"祖先的祖先是祖先"）、没有最大的数。

**专题：群。** 世界：输入卡片是群公理（结合律、单位元、逆元）。

| 关 | 加回的机制 | 产出 |
|---|---|---|
| G1 单位元只有一个 | 相等的代换 | — |
| G2 消去律 | ab = ac ⟹ b = c：两边乘逆元 | **消去** |
| G3 逆元只有一个 | 用消去 | — |
| G4 (ab)⁻¹ = b⁻¹a⁻¹（终极） | 先证 (ab)(b⁻¹a⁻¹) = e，再用逆元唯一 | — |

**挑战：** 理发师（证明不存在一个人给且只给不给自己理发的人理发：¬∃x.∀y.S(x,y)↔¬S(y,y)；跳跃：把 y 取成 x）。

### 第 4 代 · 四号（归纳与递归函数）

**能力：** 展开定义（按递归函数的定义方程改写）、归纳框（自然数，后来是列表）。这一代的引言连到《状态之图》：归纳就是"同一块电路板在每个 n 上跑一遍"，起点内板是第一格，一步内板是那块板。

**地基：** 4-1 算一算（展开 2+2 得 4）、4-2 第一次归纳（0+n = n）、4-3 用上归纳假设、4-4 列表也能归纳（length (xs@ys) = length xs + length ys）。

**练习：** 加法结合律（**结合**）、加法交换律（要用前一关的引理）、map 合并、rev 的长度、rev (rev xs) = xs（要先证 rev (xs@ys) = rev ys @ rev xs）。

**专题：排序。** 世界：自己定义的 insert、insort、sorted、count。

| 关 | 加回的机制 | 产出 |
|---|---|---|
| S1 插进有序的表 | insert 保持有序（对表归纳 + 分情况） | **插入保序** |
| S2 排好了 | insort 的结果有序 | — |
| S3 一个都没丢 | count 不变：结果是原表的一个排列 | **插入保数** |
| S4 插入排序正确（终极） | 有序且是排列 | — |

**挑战：** 尾递归求和等于普通求和（naive 解：直接对 n 归纳，归纳假设里的累加器是固定的，卡住；跳跃：先把命题加强成"对所有累加器 acc"再归纳）。

### 第 5 代 · 验证机（霍尔逻辑）

**能力：** 板上多了一段小程序，每条语句是一格，验证机像《状态之图》的机器人一样沿着程序走；它会**倒着推**（最弱前置条件，呼应远望的"倒着扫"）；遇到循环，它要一张**不变式卡片**，卡片上的内容由学习者写（手册原则 5：关键设计权交给学习者）。剩下的验证条件交给第 4 代的证明核和一个算术判定器。

**反例：** 不变式不成立或不够强时，在小范围的输入上跑程序，给出出错的那一步的具体状态（x = 3，s = 5，不变式说 s = 6）。

**地基：** 5-1 赋值、5-2 先后、5-3 分支、5-4 循环不变式（求 1..n 的和）、5-5 会停下来（递减量）。

**练习：** 不用临时变量交换两数、数组最大值、用加法做乘法、整数除法（商和余数）。

**专题一：二分查找**

| 关 | 加回的机制 |
|---|---|
| B1 从头找到尾 | 线性查找：不变式"前面都不是" |
| B2 有序就能提前停 | 不变式多一条"前面都比它小" |
| B3 每次砍一半 | 二分：不变式是"要找的只可能在 [lo, hi) 里" |
| B4 二分查找（终极） | 找不到时返回插入位置；边界全对 |

**专题二：杀死变异体**（可选，挂在 5-4 之后）。规格太弱也能"验证通过"。这一串关里学习者写的是**后置条件**：原程序要能验证通过，引擎生成的每个变异体（改一个运算符、差一的边界、去掉一句）都要验证不过。存活的变异体就是反例，告诉学习者"你的规格放过了这个错误的程序"。

| 关 | 加回的机制 |
|---|---|
| M1 求最大值 | 只写"结果在数组里"会放过返回第一个元素的变异体 |
| M2 求和 | 边界变异（少加最后一个） |
| M3 排序（终极） | "结果有序"放过了返回全零的变异体；要加"是排列" |

**挑战：** 荷兰国旗（三路划分；naive 解：两段的不变式，过不了；跳跃：四段的不变式，中间一段"还没看"）。

### 第 6 代 · 检查机（状态机与不变式）

**能力：** 程序变成几个同时运行的进程，检查机穷举所有交错，画出状态图；会检查"坏状态永远到不了"和"不会卡在谁都走不动的状态"；会检查一个不变式是不是**归纳的**（成立的状态走一步还成立）。

**地基：** 6-1 状态图（红绿灯）、6-2 交错（两个进程同时加一，丢了一次）、6-3 归纳不变式（成立但不归纳的不变式：检查机给出一个满足它、走一步就不满足的状态）。

**专题：互斥**

| 关 | 加回的机制 |
|---|---|
| X1 一个标志 | 两个进程都看到"没人"：检查机给出那条交错 |
| X2 轮流 | 安全了，但对方离开以后自己再也进不去：检查机找到卡死的状态 |
| X3 Peterson（终极） | 证明互斥：写出足够强的归纳不变式 |

**挑战：** 不变式不够归纳（给定一个正确但不归纳的不变式，加强到归纳）。

## 4. 元件从哪里来

- **原始元件**：公理 K、S，MP；每个连接词的引入、消去规则；量词规则；相等；反证法；算术判定器（第 5 代起，作为黑盒）。每个在一关里第一次出现。
- **机体能力**（不是元件，在地基里教）：假设框、分情况、任取框、归纳框、程序格与倒着推、不变式卡片、交错穷举。
- **学习者证出的引理**（封装件）：恒等、串联、拆双向、消去、结合、插入保序、插入保数……每个都必须在后面的参考解里用到（审计 `unused`）。

## 5. 引擎：复用什么，补什么

**已经在 kit 里的（`games/kit/domains/logic/`，`npm test` 覆盖）：**

- `formula.js`：命题和项的语法树、读写（符号和 ASCII 两种写法）、自由变量、不捕获的代换、约束变量改名下的相等。
- `proof.js`：推理规则就是共享引擎的元件，线上传「命题 + 还开着的假设」。MP、公理 K/S（卡片上填实例）、自然演绎的引入和消去、反证法、∀/∃（含"任取"的新变量检查）、相等的代换；→引入、∨消去、∀引入、∃消去是框（`kit/circuit/frames.js`）：框卡片下面有区域，区域左边给出它的假设，区域里证出的东西接回框的同名输入口；线只能往里走，框外的一切框里都看得见；证出的引理当规则用（`lemma`）。接错时指出要什么、接进来的是什么。
- `models.js`：反模型。命题逻辑穷举真值表，一阶逻辑在 1–3 个元素的世界里搜（结构太多就不搜，并说明搜到了哪里）。
- `validate.js`：`npm run check` 的证明检查：参考证明必须闭合目标、naive 证明不能；参考证明证的目标不能有反模型，标了 `unprovable` 的关必须有反模型。
- 编辑器侧：线的种类（`parts.wireKind`）、框（`kit/circuit/frames.js`：桌面画布上直接展开、可折叠，卡片拖进拖出，点一下区域就是新元件落下的地方；手机上框是一整行宽的块，每个区域是自己的一格格网格，开头是「假设」，末尾是「结论」的圆点，块一样能拖进拖出）。

**还没做的（按顺序）：**

1. **关卡界面和 `defineLogicGame`**：证明板（复用电路编辑器，元件卡片上填公式）、框在画布上直接展开（`frames.js`）、反模型面板。第一个原型关卡做出来时一起做。
2. **程序与验证条件（第 5 代）**：一个很小的命令式语言、解释器、最弱前置条件、验证条件。
3. **合一**：现在公理和规则的实例是填在卡片上的；接上线时自动合一出实例是更好的手感，可以以后加。

**诚实的限制：**

- 第 5、6 代的验证条件涉及算术。用小范围枚举去"判定"它们，原理上不完备（可能放过在范围外才出错的程序）。两条路：(a) 每关声明变量的取值范围，引入里明说"在这个范围内检查"；(b) 只做线性整数算术的判定（Fourier–Motzkin 或一个小的 Presburger 过程）。建议先做 (a)，再在第 5 代的参考解上评估 (b) 的必要性。
- 命题在手机格位里会很长。需要早做一个原型，试一下"缩略 + 点开看全文"够不够用。
- 合一失败的提示容易变成天书。要求只指出**第一个**对不上的子项，并排高亮。

---

## 6. 建议的第一步

先做第 0–2 代的竖切原型：命题逻辑只需要合一、假设框和真值表，引擎量最小，同时能验证两件最没把握的事——命题在手机上能不能读、"框"这个嵌套子板好不好用。这两件事通过后再写第 3 代起的逐关规格。
