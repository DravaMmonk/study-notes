# 《证明完毕》设计框架：造一台通用证明器

《证明完毕》（Q.E.D.，id `qed`）的专题是**证明器本身的机制**：Isabelle 和 Lean 这样的交互式证明器，里面到底是怎么运转的。学习者从真值和语法树起步，一层层亲手造出一台小小的通用证明器：可信的证明核、自然演绎、带元变量的规则消解、能回溯的策略、经典推理、化简器、证明即程序、归纳类型、依赖类型与相等、自动化和证书，最后用结构化证明把它们串起来。所有类图灵完备游戏共同遵守的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；本文档只记录这个专题自己的内容。改课程之前先改这份文档，过时的内容随改随删。

**主线：学 Isabelle 与 Lean 搭证明器核心的思路。** 只借它们构建证明器核心（元件）的思路：小证明核、规则与合一、策略、化简、归纳；分歧处（Isabelle 是 LCF 式的：定理是抽象类型，核只认规则，不留证明项；Lean 是依赖类型的：证明是项，核检查项的类型）各做成元件，不做成「两个软件的对比课」。元件和写法按游戏的需要定，不照搬任何一个软件的界面或语法细节（第 13 章的证明项借 Lean 的写法，因为它最短）。

**名字少提，百科详讲。** 关卡文字（引入、简报、提示、点题）只在引入里少量提一下软件的名字，说清「这里迁移了谁的思路」，一章至多一两处；软件本身的设计、历史和取舍写在百科（`glossary.js`）里，如「证明助手：Lean 与 Isabelle」「证明即程序」「世界与反模型」。

**课程对照（次要）：** COMP30026 Models of Computation（25S2）的逻辑部分（笔记 `docs/Unimelb/25S2/MoC/` 01–05 篇）和第 0–6 章大体重合，用作例题来源；计算理论部分只保留「为什么证明器不能全自动」这一条（第 11 章专题「机器做不到的事」）。

**排章的规矩。** `games/DESIGN.md` 第 1 节的三条（不依赖的就分支；引言写的是组装；基础元件保持最少），加上第四条：**一个机制放在它被核心用到的地方，不放在最早能证出它的地方。** 德摩根、排中律第 4 章就能证出来，可它们真正派上用场在后面：排中律和反证法是 auto 撞上的墙（第 9 章）；双重否定、去掉箭头、德摩根这些等价律大多要靠反证法或排中律才证得出，紧跟着在第 9 章证完，第 10 章的化简器只拿它们改写，不再停下来证。证明项也一样：第 7–10 章的机器用不上它，归纳类型和依赖类型才建在它上面，所以它是第 12 章，紧挨着这两章。

**元件箱只留持续可用的元件。** 不再持续用的元件都标成留在带来它的关里（`local`，`levels/index.js`，不进元件箱、不上地图，文案里直接写名字）；后面哪一关要用，就在那一关的 `adds` 里再带来：合一的六个原始元件和高阶模式（合一器搭好后由规则卡接手）、合一器、全部引入规则和全部消去规则（auto 里面）、往前推、放到最后、证明板上的归纳框、合并和交换、Skolem 化、拆成子句、证明板上的归结、归结一圈、饱和器、化成子句、重放（都进了重建器）、别人的证明器。去掉等价不标：内置的化成子句要从规则书里读它。

**现状：** 第 0–15 章都已做。规格在 `spec.js` 和 `levels/`，界面和规则在 `kit/domains/logic`。存档迁移见 `spec.js` 的 `saves`。

**终点：** 学完以后，学习者手里有一台自己造的证明器，并且知道它的每一层是怎么来的：

- 证明核很小，定理只能由核规则产生，所以再聪明的自动化也造不出假定理（LCF）；一个证明也可以是一个项，核只检查它的类型（de Bruijn 准则）；
- 规则消解靠合一：带元变量 ?P 的规则和目标合一，目标换成规则的前提；合一的解可能不止一个，所以要回溯；
- 证明状态本身就是一条定理（Isabelle）或一组元变量（Lean），策略是产生证明的程序，组合起来就是 `auto`；
- 只用引入和消去规则的 auto 证不出排中律：经典推理要多一条反证法，它没有对应的程序；
- 化简是按方程定向改写，配上条件、合同规则和定义展开；
- 证明是程序：→ 引入是 λ，套用是函数应用，∧ 是有序对，∀ 是依赖函数，证明里的弯路算掉就是 β 归约；
- 归纳类型自动给出构造子、递推子和归纳原理，递归要证终止；
- 相等也是一个类型：改写就是给出一个「动机」；定义相等和命题相等不是一回事；
- 自动证明器找到的证明要变成核能检查的证书；而且证明器不可能全自动（一阶逻辑的有效性只是半可判定）。

看到 Isabelle 的 `thm`、`⋀`、`⟹`、`?P`、`rule`、`erule`、`back`、`THEN`、`simp add:`、`datatype`、`fun`、`induction`、`sledgehammer`、`metis`、Isar 的 `have … show`，Lean 的 `fun x => …`、`⟨a, b⟩`、`exact`、`apply`、`?m`、`rfl`、`▸`、`Eq.rec`、`induction … with`、`decide`，能说出它对应自己造的哪一块。

## 1. 映射：把《图灵完备》搬到证明器上

《图灵完备》从 NAND 造出计算机，最后用自己的计算机写程序。这里从真值和两块核元件起步，造出证明器，最后用自己的证明器证定理。每一章给证明器装上一个模块，线上传的东西往往也换一次，这就是抽象在上升：

| 章 | 线上传的东西 | 元件是什么 |
|---|---|---|
| 真值电路 | 真值（是 / 否） | 连接词的门 |
| 证明核、连接词、量词规则 | 定理（「这句已经证出来了」） | 推理规则；证出的引理 |
| 量词的语言与反例 | 公式（玩家用块拼）；世界 | 拼公式板、造世界板 |
| 规则与元变量 | 等式组；目标与规则（带 ?P） | 合一的规则；用规则、已知里有，其余由它们搭出 |
| 策略 | 证明状态，可能有多个结果 | 框（几条路、重复、每个目标、搜到证完）和搭出的策略 |
| 经典逻辑 | 定理；证明状态 | 一条新的核规则反证法，和用它证出的引理、等价律 |
| 化简器 | 证明状态（要化成某个样子的句子和等式） | 改写一处；由它搭出的化简 |
| 归纳类型 | 证明状态 | 类型声明生成的构造子、递推子、归纳规则 |
| 证明即程序 | 定理和它的证明项 | 同一套规则，卡片上同时显示证明项；写证明项板 |
| 依赖类型与相等 | 定理与证明项 | `rfl`、改写的动机、依赖类型 |
| 自动化与证书 | 子句集，然后是重建的证明 | 子句形式、归结、饱和器、证书重建 |

| 《图灵完备》 / 已有几款 | 证明完毕 |
|---|---|
| 原件 NAND | 第 1 章是连接词的门（∧、¬ 起步），第 2 章起是证明核的两块元件（套用和假设框，Lean 内核的函数应用和 λ）；K、S 用框证出来当元件，专题拿掉框只用 K、S 和套用，那份费劲说明框为什么是基础元件 |
| 搭好的电路变成元件 | 证出的引理、组合出的策略、化简、重建器都变成元件。黑盒和"搭出它的那一关"必然一致：引理的陈述就是那一关的目标；策略、化简用那一关的测试校验 |
| 测试 + 反例 | 证明关的目标就是规格，目标是假的时给反模型；策略和化简的测试是一组目标，逐个跑、逐步回放 |
| 机体 | 只有一台：玩家自己的证明器，每一章装上一个模块。第 4 章起每一章都写 `keeps: 'all'`：装上的模块一直在证明器里，每种板只摆出它认得的元件 |
| 用自己的 CPU 跑程序 | 策略一章，用自己组合出的 `auto` 重新解连接词一章的关；最后一章用整台证明器写结构化证明 |

**要练出的思维：** 先找反例再找证明；分清语法和语义（⊢ 和 ⊨）；从结论倒推、把目标拆成子目标；证明是可以检查、可以计算、可以由程序产生的对象；引理与复用；加强归纳假设；知道自动化的边界在哪里，以及为什么它的结果仍然可信。

**叫法。** 「证明器」只指玩家整局在造的那整台东西（各章装上的模块）。证明板上接出的是一个证明：简报写成「已知「A → B」「B → C」，证明出「A → C」。」，用字母写的形状（由关卡的 schema 自动生成，`kit/domains/logic/course.js` `proofBrief`；没有已知时写「不需要任何已知，证明出…」，目标是 ⊥ 时写「证明出矛盾」；要读证明项的关按名字列出已知；额外的限制写在 `briefNote` 里，如「不用假设框。」「证明项要是 p q r。」），式子里每个连接词套在另一个里面都保留括号（A ∨ (B ∧ C)），测试案例照旧用下雨、刮风这样的句子。带故事的关（岛民、理发师、卡罗尔、自然数、哥德尔）手写简报，也用「已知…，证明出…」。玩家看到的机器板叫「证明助手」：机器关的简报一律写「设计一个证明助手……」（英文 Design a proof assistant），文案里不说「机器」；真值电路一章和专题「机器做不到的事」（图灵机）不在此列。文档和代码里仍叫机器板。

**机器板上，规则也是元件。** 用规则、规则对已知、往前推、改写、化简这几种元件，不在元件上选规则：它们多一个输入口「规则」，接进一串规则。规则从规则元件来：
- 每一条规则都在一个元件里。核的规则就是证明板上的那个元件（→ 引入、消去 ∧……），证出的引理也是它自己的元件；关卡自己的公理（关卡的 `rules`）和「已知里的等式」也各是一个元件。数与列表的规则合成一个元件**数理规则书**（`math`）：数据类型给的规则（`datatypes`）、定义里的等式（`defs`）和已经证出的等式（课程的 `facts`，见第 12 章），按这个次序列在它上面。专题的公理和数理规则书只属于写出它们的关：写了它们的关自动带来它们，它们留在原地（`local`），不进元件箱；核规则、引理照课程的规则一直带着。托盘照常只展开参考解用到的，其余折叠。
- 规则元件输出一串规则。它有一个输入口「前面」：接进另一串规则时，输出那一串再加上自己，几张规则元件串起来就是一串。一个元件含几条规则时（拆开 ∧ 有左、右两条；分离有三种用法；引理有几个形状），元件上列出它给的规则：下拉框添加一条（加在最后），每条旁边的 × 去掉它（至少留一条，默认第一条）；按添加的次序接在「前面」那一串后面。规则元件的卡片只列它自己给的这几条，不再把整串（连同「前面」接进来的）列一遍；说明和悬停提示也不写具体的规则，元件箱里另有一张表列出每个元件给出的规则（引理按已经得到的形状）。
- 用规则的元件按顺序用这一串：用规则、规则对已知、往前推、改写用第一条用得上的（回溯打开以后，每一条的结果依次都给出）；化简整串按顺序轮着用，和原来排在元件上的那一串一样。接进来的规则这种元件用不了（拿推理规则去改写，拿定义去用规则），元件说出来。
- 规则串、元件上的规则和元件箱里的规则表都写出公式本身（`⟦?A; ?B⟧ ⟹ ?A ∧ ?B`、改写写成 左 ⟼ 右），不写规则的名字。
- 规则串是常量：规则元件可以摆在框外，接进框里的元件。

**机器板上搭出的元件跑玩家自己的电路。** 消去规则生成器、合一器、规则对已知、往前推、拆目标、用已知、auto、化简、化成子句、饱和器、重建器没有内置实现：每一个都跑玩家通过搭建关时的那块电路（`machine.js` 的 `builtParts`，外壳记在 `progress.built`；没通过就开着的用参考解）。元件的输入口就是搭建关板上的输入；里面的元件用的规则是用它的那一关和搭它的那一关的规则书合起来的，用它的那一关或搭它的那一关能回溯，里面就回溯。所以 auto 一步一步地跑：步进时每一步写明它在哪块元件里（`auto › 拆目标 · 第 3 步 › 用规则`）；桌面上展开元件、手机上点开元件，就看到那块电路（只读），每个元件显示它最近一次运行里的值，正在算的那一个亮起；「编辑」跳到搭它的那一关。规则元件只给出一串规则，不算一步。auto 一类的关一组测试有几百到几千步：用运行快进看，用步进停下来看里面。

所有板共用 kit 的电路编辑器、反模型面板和步进回放（`shell/usePlayback.jsx`）。一个问题换一种板再做一遍时，用一关几段任务（`tasks`）：先找反例再证明、先证出引理再拿它当新板的元件、先接线再读证明项、先手证再让机器证，都是这一种。后一段接着前一段的电路往下做时，这一段标 `carries`，打开就是前一段接好的电路，不用再搭一遍。过关点题附上同一件事在 Isabelle 和 Lean 里各自的写法（只展示，除第 11、14 章外不要求学习者写）。

## 3. 课程

后面各章按 `games/DESIGN.md` 现行的规则排：

- **一章装一个模块，不塞两个。**
- **互不依赖的机制排成并行组**（一组最多三路），每路是「新机制 → 3–5 关练习」，练习按维度变（换外观、换方向、加层数、去支架、组合、辨真伪）；几路汇合后再练组合。只是换一种眼光重看旧东西的章（第 13 章），同一个点的小任务并进同一关。
- **新元件有前因。** 能证出来的部件都由玩家证出：化简用的等价律、归结规则都是先在证明板上证出，过关后成为别的板的元件。用法抽象、光看说明会用错的原始元件有单独弄清用法的一关（`showcase`）：重复框、任取框、拿出那一个、用规则、回溯、改写的动机。
- **基础元件最少。** 能由已有元件接出来的，一律由搭建关造出；第 4 节逐章列出原始元件和它为什么接不出来。
- **一个机制放在它被核心用到的地方**（见开头）。
- **造出的东西后面要用，而且用在不用它会很长的地方。** 去处见第 4 节。
- **专题只给有意义的应用或长线问题**，一个专题是同一个问题在长大：岛民（第 1、8 章，第 11 章再长大）、族谱（第 5 章查询、第 8 章推理）、卡罗尔的推理题、插入排序、机器做不到的事（第 11 章，从说谎者长大）和不完备性（第 12 章，再从停机问题长大）。
- **挑战难在一个跳跃**，都带会失败的 naive 解；挑战和专题造出的东西，只有依赖它的关卡能用。

### 第 1 章 · 真值电路（语义）　已做

**模块：** 证明器的第一块：一块门电路算出一句话在一行上的真值，机器把它在真值表的每一行各跑一遍（像《状态之图》的机器人逐格扫表）。原始元件是「非」「与」两个门；「或」「若…则…」由玩家拼出，拼出即解锁（运行时是内置实现，`validate.js` 对照搭出它的那一关检查）。关卡种类 `gates`（`kit/domains/logic/gates.js`、`ui/GatesScreen.jsx`）。

**地基**

| 节 | 关 |
|---|---|
| 门 | 不是不下雨（两个「非」）、下雨但没刮风（「与」）、「非」管到哪里（同样两个门，接的先后一换就是另一句话：语法树决定意思；naive 解是另一种接法） |
| 造门 | 下雨或者刮风（只用「与」「非」）→ **或**、如果下雨那么地湿（用上「或」）→ **若…则…** |

**练习 · 三种句子：** 怎样都对，怎样都错（一关两个任务：永真式、矛盾式；输出那一列说明一切）、两个方向都对 → **等价 ↔**（门，专题里每一句「某人说」都用它）。这几关隐藏目标真值那一列（`hideTarget`），否则表格直接透出"全真""全假"。

**专题：把谜题接成电路**（MoC 01：把问题编码成公式，再看哪一行满足）。这几关连句子也只用话说出来（`blind`）：专题练的是把自然语言翻译成逻辑语言，每关多一种说法的译法，过关点题写出完整的译文，等价的译法都算对；真的那一行就是答案。

| 关 | 加回的机制 |
|---|---|
| E1 翻译成与或非 | 把一句话（「a 和 b 不都是骑士」）翻译成与、或、非：「不都是」和「都不是」的区别（naive 解是后者） |
| E2 a 说的话 | 新译法：「a 说 X」=「a 是骑士」与 X 等价（用「等价」门）；naive 解只译一个方向 |
| E3 一个人说话 | 新译法：「a 是无赖」= 非（a 是骑士） |
| E4 两个人说话 | 新译法：几个人的话都对得上 = 各句的翻译用「与」接起来；「我们俩都是骑士」= a 与 b |
| E5 三个人说话（终极） | 「都是无赖」正是 E1 的陷阱「都不是」；八行；人数每多一个，行数翻一倍（为归结一章埋下动机） |

### 第 2 章 · 证明核　已做

**能力：** 证明核，两块基础元件：**套用**用掉一句「若…则…」，**假设框**造出一句（Lean 内核的函数应用和 λ；Isabelle 元逻辑 Pure 里 ⟹ 的引入和消去）。证明核以外的一切都是证出来的元件。

**地基：** 照抄，然后两条并列的线：套用（「套用」两个任务：套用，用不着的已知；「一句里套着一句」两个任务：剥掉一层，再整句当前提），假设框（「加一个假设」两个任务：一个已知加一个框，讲清假设和结论两个圆点；再加一层框）。两条线都走完，「造一台证明器」把两块元件合起来练。接着拿封装件搭：两条并列的线，只用框造出串联（接起来、换一换条件的顺序造出交换）∥ 合并（同一个条件说两遍），三块一起练（「绕一大圈」三个任务：接起来再合并、绕一大圈、对不上的两句）。串联是第一块封装件，「接起来」关后点明**封装就是定义**：给一段证明起个名字（Lean 的 `theorem` 就是一个 `def`），用到它的地方都能换回那块电路，所以证不出任何框证不出的东西；公理不一样，它说的是一件新的事（术语表「引理」「定义」从这一关打开）。串联、交换、合并从此是常用工具：后面每一关只要持有，托盘上都摆出来，不折进「更多」（课程的 `staples`）。最后 K 一条线（「多一个条件也无妨」两个任务：先一个框证出「它 → 它」，结论就是框自己的假设；再两层框证出 K，造出元件 K；关后说 K 和串联一样是定义，只有公理的证明器只能把它当出发点）和 S 一条线（「在条件下套用」：三层框证出 S，造出元件 S）。

**专题「拆掉框」（K、S 都到手后打开）：** 关卡的 `without` 拿掉框。X1「不用框：K 和 S」两个任务（K 加一次套用；S 加两次套用），然后分成两个分支：不用框串联（讲演绎定理：任何框都能换成 K、S 和套用，所以框不增加能证的东西，只让证明好写）、不用框交换（S、K，再用 K、S 接起来，8 步）；另一支是不用框恒等（5 步，关键是 S 的第二句选「它 → 它」）、不用框合并（S 加上一关拼出的恒等，8 步）。证明核没有挑战关。

**不另做「核可靠」一节：** 可靠性不是一块能接线的元件（造出来也没有后面的参考解能用，审计 `unused` 会报）。它在两处讲：连接词一章的辨真伪关（真值表上有一行是假，所以证不出来：证出来的一定是真的，⊢ 推出 ⊨）；策略一章的点题（策略只做核规则做得到的事，自动化造不出假定理）。

### 第 3 章 · 声明　已做

**问题：** 怎样把「与」「或」「非」引入证明核？第 2 章的封装件是定义，起多少名字能证的都不变；连接词要声明。

**声明（三关，每关两段，`levels/declare.js`）：** 声明「并且」、声明「或者」、声明 ⊥。第一段在声明板上写出引入规则（`kind: 'iso'`，`kit/domains/logic/iso.js`、`ui/IsoScreen.jsx`）；第二段在消去板上手写它的消去规则（`kind: 'take'`，`kit/domains/logic/take.js`、`ui/TakeScreen.jsx`），由一套检查确认它不多给、也不少给。动机按自己的思路讲：定义只是给框和套用证出的东西起名，起多少名字能证的都不变；「并且」是证明核根本说不出的话，只能声明：说清它怎样才算证出来，再说清拿到它以后能做什么。一个连接词由它的引入规则引入，每条引入规则是一条用假设式写的新规则（对应 Lean 构造子的类型 `And.intro : A → B → A ∧ B`，对照只写在百科和 §5）。两段都通过后，引入规则和消去规则成为证明板元件（关卡的 `adds`：引入 ∧ / 消去 ∧、引入 ∨ / 消去 ∨、矛盾推出一切），元件说明写明来自哪个声明。证明板上的消去规则是标准的情况形式，不管玩家写的是一条还是一组（第 4 章再由它证出拆开 ∧）。
- **板上**：开局只有连接词卡（锁住）。假设卡从托盘拿，卡上用下拉框选它假设哪一句（新拿的一张默认选板上还没有的那句），可以删。连接词卡是板的输出。桌面上卡都能拖动；手机上连接词卡固定在输出行，假设卡在格子里，可以挪。
- **写引入规则**：一张假设接进另一张的「先假设」，就是同一条引入规则要两样，顺着线读（A 接进 B 的「先假设」是柯里化的 A → B → 它）；假设接进连接词卡的一个引入规则口，就是一条引入规则。连接词卡的输入口从一个开始，每接上一条引入规则就多一个（最多三个），断开中间的引入规则时后面的往前补（`settle`）。卡上的内容用证明板显示句子的样式，每样只写一次：假设卡只有它假设的那句；连接词卡逐条写出引入规则的规则（前面标 1. 2.，详情里写「引入规则 1」；不用圈号，免得和板上元件的编号 ①② 撞），按全游戏规则的写法用 ⟹，比如「⟦下雨; 刮风⟧ ⟹ 下雨 ∧ 刮风」，再写证不证得出。百科「规则箭头 ⟹」从声明「并且」起开放，讲清 ⟹ 和 → 的关系（Isabelle 分 Pure 和 HOL 两层，Lean 只有 →，Curry–Howard）。写成证明，它就是两层假设框；声明的规则框里没有证明、结论由声明给出，所以画成一串假设卡，不画成框（试过框：框里不开假设、只放另一个框，误导成「里面有证明」，还占地方）。
- **手写消去规则（消去板）**：和声明板反着来。声明板上，假设是交进去的东西（输入）；消去板上，它们是收到的东西（框里开出来的圆点），形状和证明板上的消去 ∨ 一样。左边是一张锁住的「它」（声明的那句话，一份封好的证明），接进一个消去规则框；框上选有几种情况（几个区域）和结论（?R，任意一句；或者关卡的某一句）。玩家往每个区域里放「收到」卡（选一句话）和「收到一样东西」卡（⋀x）：这一种情况打开时，手里会有这些，用的人拿它们推出结论。区域没有结果口，不用接线：推出结论是用这条规则的人的事。托盘里还有消去规则框：可以写一组（比如取左、取右两条，各零种情况），检查按整组判。框上用全游戏规则的写法写出它：⟦它; (⟦A; B⟧ ⟹ ?R)⟧ ⟹ ?R。
- **检查：不多给，不少给**（`take.js` 的 `checkTake`，即证明论的和谐），做成**两类测试用例，不写一句解释**，每行只有句子：左边是输入，右边是用的人最后手里有什么，末尾 ✓ / ✗。两类都归结为同一个小问题：一组已知句子、一组办法（⟦假设⟧ ⟹ 结论，⋀x 的假设能对上任何东西），能不能推出某一句（饱和到不再变）；?R 当作一句谁也不认识的新句子。
  - **开盒**（每条引入规则一行，**开盲盒**）：一份由这条引入规则造的证明，运行到这一行才打开，显示里面装着的东西（取的东西换成新名字）；右边是每条消去规则交到用的人手里的东西（走进的那种情况收到的，或直接得出的结论），盒子里没有的标红。每条消去规则的结论都要从盒子里的东西推得出，否则多给了。tonk 在这里被拦下。⊥ 没有引入规则，没有这一行。
  - **任意 ?R**（最后一行）：一份封好的、不知道怎么造的证明，加上每条引入规则各一张「交进去的东西 ⟹ ?R」；先用玩家的消去规则（一条的情况都推得出它的结论，它的结论就加进已知），最后要推得出 ?R，否则少给了：单写一条取左的，或者把结论定死成一句的。
- **测试是情况**：声明板上，手里有哪些证明（带编号），这时该不该证得出；证得出时用第几条引入规则、消去规则取回什么或走哪种情况。规格只能拿情况去测。三关的典型错误：「并且」两张假设各接一个口（只有一份时也证出了），「或者」两张串在一起（只有一份时证不出），⊥ 接了假设。消去板上的典型错误：「并且」的消去规则只写一条取左（少给），「或者」写成一种要两样的情况（多给），⊥ 多写了情况（少给：哪条来路也推不出那种情况要的东西）。
- 关后点明：声明的规则不是证出来的，「并且」原本不存在，规则本身就是新的；消去规则是手写的，所以要检查：声明说的是「只有这几条来路」，消去规则只能把交进去的东西交还（不多给），也得交还全部（不少给）；它的可证范围正好是每条来路的可证范围的交。⊥ 没有引入规则，所以它的消去规则一种情况都不用写，有了它想要什么都行；¬A 只是 A → ⊥ 的名字，是定义，不用声明。百科「声明」与「定义」「公理」并列，「消去规则」讲和谐。
- **可选专题 D · 更多声明**（接在声明 ⊥ 后，同在 `levels/declare.js`）：每关一条引入规则的形状。「三样」两个任务：三样都要（一条引入规则串三张；关后点「A ∧ B ∧ C」读作「A ∧ (B ∧ C)」）、三选一（三条引入规则，引入规则口用满）；换个顺序（先要刮风再要下雨的「并且」：情况分不出顺序，用关卡的 `ways` 查规则本身，对照 `And.intro`）；至少两样（三条引入规则各串两张，同一句拿多张卡；声明的是新命题「提案通过」而不是连接词；关后点明「恰好一人」写不出：引入规则只说有了什么造得出，说不了有了什么造不出）；声明「真」（托盘多一张「不用假设」，一种空引入规则，`True.intro`，和 ⊥ 对照）；声明「当且仅当」（假设卡可选带 → 的句子，`Iff.intro`）。关卡的 `tray` 决定托盘里有哪些卡，`sentences` 是假设卡可选的句子。至少两样、声明「真」、声明「当且仅当」各有第二段，在消去板上写它的消去规则（三种情况各要两样；一种不要假设的情况；一种要两句 → 的情况），是手写消去规则的练习。
- **工作单：专题 D 的最后一关「别人的声明」**（tonk，辨真伪；Prior 1960）：板上预置别人的两块证明板元件（`local`、`preset`）：引入规则和「或者」的一条一样（由 A 造出 A tonk B），消去规则却和「并且」的一条一样（由 A tonk B 取出 B），没有经过检查。第一段在证明板上用它们从「下雨」证出「地湿」：什么都证得出；第二段把别人的消去规则摆上消去板，看检查在「不多给」那一行拦下它。点题：消去规则不经检查就收下，就能证出任何东西。

### 第 12 章 · 数与列表　（29 关，`levels/inductive.js`）　已做

### 第 14 章 · 依赖类型与相等（Lean 一侧）　（15 关，`levels/equality.js`）　已做

**动机：** 化简器把等式当改写规则用，数与列表一章证出了一串等式；可等式本身是什么？在 Lean 里，a = b 也是一个类型，它的证明项只有一条引入规则 `rfl : a = a`，用它是 `Eq.rec`（写作 `h ▸ e`）：由 a = b 和关于 a 的一句，得到关于 b 的那一句，换掉哪几处叫**动机**。核检查类型时会按定义去算，所以算得出来的相等（定义相等）用 `rfl` 就证完，算不出来的（命题相等）要证明。核会算，就有了**反射**（Lean 的 `decide`）：判定程序写成定义，证明一次它是对的，以后每一题只要核把它算出来。类型还能依赖一个值：长度写在类型里的向量 `Vec n`。Isabelle 的 HOL 是简单类型，相等是原始常量，`subst` 直接换。

**工作单：索引由生成器处理。** 第 6 章声明相等时，消去规则（等量代换）现在由关卡给出（`levels/declare.js` 的 `take`）。改成：这一章升级消去规则生成器，处理带索引的声明（引入规则的结论 a = a 在索引的位置上和声明的句子不同，情况里的那个位置成为动机的参数），生成 `Eq.rec`；做完删掉 `take` 和这一段。

**这一章没有新的原始元件。** 第 6 章的等量代换就是 `Eq.rec`：卡片上点的框就是动机，它的证明项是 `h ▸ p`；自反就是 `rfl`。写证明项板（`term`）添两块：`rfl` 和 `□ ▸ □`（关卡的 `forms` 说一关拼条上有哪些块）。核（`pterm.js` 的 `checkTerm`）添三样：`h ▸ p`（要证的那句里把 h 的一边换成另一边，就是 p 要证的；两个方向都试）；关卡有定义时，比较两句话先按定义算到底（`rewrite.js` 的 `defNormal`）；`∀x. A → B` 用在一个证明上时，x 由那个证明的类型读出来（Lean 的隐式参数）。向量写成命题：`Vec(n)` 是一个类型，它的证明项就是一个长 n 的向量（只记长度，不记元素）；`vnil : Vec 0`、`vcons : ∀x. Vec x → Vec (S x)`、`append : ∀x y. Vec x → Vec y → Vec (x + y)`、`tail : ∀x. Vec (S x) → Vec x`、`head : ∀x. Vec (S x) → Elem` 是关卡的已知。证出的等式（第 12 章的加零、加后继……）也是已知，用法和第 12 章的「对所有」一样：`addZero m`。

| 路 / 段 | 关 |
|---|---|
| 相等是类型 | rfl（章首：写证明项 `rfl`、`fun a => rfl`）、等量代换就是 Eq.rec（四段：证明板上接等量代换，读它的证明项 `h ▸ p`；再在写证明项板上写 `h ▸ p`，两个方向，再接着用；showcase：点的框就是动机）、对称（`h ▸ rfl`）、传递（`q ▸ p`，`p ▸ q` 也行）、换哪几处（证明板：只换一处，naive 全点；两个方向都要换，先倒过等式） |
| 两种相等 ∥ 依赖类型 | 计算就相等（加法的定义下 `rfl : 1 + 1 = 2`、`fun a => rfl : ∀x. 0 + x = x`）、判定程序（机器板：化简按定义算出 taut f 是真是假，公式写成数据 Or p (Not p)；引入回指证书那一关：另一条路不找证书）、让核来算（证明项板：已知 sound : ∀x. taut x = 真 → Taut x，`sound rfl`，x 从要证的那句读出；naive `rfl`）、算出来是假（已知 complete；给出的 `sound rfl` 改成 `complete rfl`；一对）、要证明的相等（x + 0 = x 算不出来，`rfl` 不行，用加零；类型里的 0 + m 直接当 m 用，m + 0 要 `▸` 搬）∥ 长度写在类型里（用 vnil、vcons 拼出长 2 的向量，vcons 的长度由参数读出）、只对非空的有定义（head：空向量取不出第一个，核拒绝 `head vnil`） |

### 第 15 章 · 结构化证明（毕业）　（10 关，`levels/structured.js`）　已做

**动机：** 真正的证明文本是写给人看的结构：Isar 的 `assume … have … show`，Lean 的 `have`、`show … by`。这一章没有新的原始元件：脚本的每一行就是证明板上的一张卡片。

**写脚本板**（`kind: 'script'`，`kit/domains/logic/script.js`、`ui/ScriptScreen.jsx`）：脚本是一行一行，每行选出来，不打字：`have`／`show` 一句话（从关卡的句子和它们的每个部分里选），`using` 点选用到的事实（已知按名字，前面的行按位置叫 h1、a1、o1），`by` 选一条规则（按卡片名字和 Isabelle 的规则名列出）、一台造好的策略（auto、simp 用关卡的化简集合 `simp`、metis、对声明的类型归纳），或者一块（`proof … qed`）。块里第一句是 `assume`（假设框）或 `fix`（任取）；`obtain` 拿出「存在」说的那一样东西（拿出那一个）；块以 `show` 结束。检查时每一行都是一个小证明状态：规则 = `rule` 后用 using 的事实收掉每个前提，策略就是机器板上的那张卡片，所以每一行都落到核规则上。`locked` 的任务只让改 `by`（读脚本）。证明板关可以带一段 `script`，简报里照 Isar 的样子印出来（读完再接线）。

| 路 / 段 | 关 |
|---|---|
| 读脚本 | 一句一张卡片（章首；两段：选每行的 by，再照脚本在证明板上接线）、块套着块（同样两段：两层框）、by 后面是一台机器（选规则、auto、metis） |
| 写脚本 | 补一句 have（两题：给出 show，往前补）、一行就够（by auto；auto 证不出的皮尔士律 by metis；by simp 算加法） |
| fix ∥ obtain | fix 是任取 ∥ obtain 拆开 ∃ |
| 整段脚本（练习） | 骑士与无赖（假设 c 是骑士，metis 找矛盾）、倒两次（`by (induction) simp`，化简集合里有倒过拼接）、毕业：理发师（obtain、auto 取一个、metis） |

**没做的：** `calc` 和按情况分的块（`proof (cases)`）。相等的一串可以一行 `by simp`，分情况可以交给 auto 或 metis；这两种块各要一套新的块结构，换来的只是写法。

**收尾点题：** 每一行都落到核规则上；自动化补小步，人写结构和关键引理。

| 机制 | Isabelle | Lean | 这里 |

| 可信的核 | `thm` 是抽象类型（LCF） | 核检查证明项的类型 | 第 2 章；第 13 章 |
| 元逻辑 | Pure：⋀、⟹、`?P` | 依赖类型论本身 | 第 2、5、6 章 |
| 用规则 | `rule`、`erule`、`frule`、高阶合一 | `apply`、元变量 `?m` | 第 7 章 |
| 策略 | 结果序列、`THEN`、`back` | tactic monad、`<;>`、`first` | 第 8 章 |
| 经典推理 | HOL 本来是经典的 | `Classical.em` 是公理 | 第 9 章 |
| 化简 | `simp`（条件、合同、有序重写） | `simp`、`rfl`（定义相等） | 第 10 章 |

| 证明语言 | Isar | 项模式、`have`、`show … by` | 第 12、14 章 |

### 5.1 每个元件的真实依托

**规矩：** 目标是让玩家理解证明器为什么可信、怎么运转，所以玩家造出、用到的每个元件都要有真实依托：它的行为等于 Isabelle 或 Lean 里某个具体的东西（方法、策略、规则、核的检查），或者教科书里的标准算法，并且写明是哪个。两个系统做法不同的地方做成分岔，点明各自怎么做。为了教学故意做得和真实系统不一样的（**例外**），要有理由，并且在关卡文案里告诉玩家真实系统怎么做。不发明两边都不是的第三种语义。

**证明板的基础元件只有三类：** 证明核自带的（套用、假设框、任取、取一个：→ 和 ∀ 就是核里的函数类型）；玩家声明出来的（并且、或者、⊥、存在、相等、自然数的引入规则和消去规则，各在用到之前的声明板上造出）；公理（反证法）。其余都是证出来的封装件或搭出来的机器。关卡文案按自己的教学思路讲动机，不在前期提 Lean、Isabelle、HOL；对照写在百科和本节。

状态：✓ 有依托；≈ 有依托，做了简化，理由写在表里；✗ 和真实系统不符，待改。

| 元件 | 依托 | 状态 |
|---|---|---|
| 套用、假设框 | 核自带：Lean 的函数应用和 `fun`；Pure 的 ⟹ | ✓ |
| 引入 ∧、消去 ∧、引入 ∨、消去 ∨、矛盾推出一切 | 引入规则是玩家的声明（Lean 的构造子）；消去规则玩家手写，经检查收下（Lean 内核从构造子生成递推子：`And.rec`、`Or.rec`、`False.rec`；Isabelle 的 `conjE`、`disjE`、`FalseE`） | ≈ 真实系统不让手写，直接生成；手写加检查（和谐：局部可靠、局部完备）是为了让玩家看清它为什么只能是那样，第 12 章再交给生成器 |
| 消去规则生成器 | Lean 内核的 `mk_rec_infos`：每个构造子一个 minor premise，构造子的类型把结论换成 motive | ≈ 第 12 章造出，只做非递归、不带索引的声明；归纳假设和索引是第 12、14 章的工作单 |
| 拆开 ∧ | Lean 的 `And.left`、`And.right`（由递推子定义）；Isabelle 的 `conjunct1`、`conjunct2`（由 `conjE` 证出） | ✓ 第 4 章证出 |
| 任取、取一个 | 核自带：Lean 的 `fun`、应用（依赖函数类型）；HOL 的 `allI`、`spec` | ✓ |
| 举例、拿出那一个 | 玩家声明「存在」、手写它的消去规则：Lean 的 `Exists.intro`、`Exists.elim` | ✓ 第 6 章声明板、消去板 |
| 等量代换、自反律 | 由玩家声明相等生成：Lean 的 `Eq.refl`、`Eq.rec`（`▸`）；HOL `refl`、`subst` | ✓ 第 6 章声明板 |
| 数学归纳法（证明板） | 由声明自然数生成：Lean 的 `Nat.rec`；HOL `nat.induct` | ✓ 第 12 章声明板 |
| 反证法 | 两边都是核外的公理：HOL 的 `True_or_False`（`ccontr` 由它推出），Lean 的 `Classical.choice`（`Classical.em`、`byContradiction` 由它推出） | ✓ 第 9 章说明它是公理：证明核证不出，也没有声明给得出 |
| 合一的六条规则、合一器 | Martelli–Montanari 的合一算法（教科书算法） | ≈ 真实系统的合一是一体实现，拆成六步是为了能亲手搭 |

| 用规则（接一串规则） | Isabelle `rule r1 r2`：依次试，带回溯；Lean `apply` | ✓ |
| 已知里有 | Isabelle `assumption`；Lean `assumption` | ✓ |
| 规则对已知 | Isabelle `erule`：对上的那条已知会被删掉 | ✗ 现在保留那条已知 |
| 往前推 | Isabelle `frule`（保留原已知）；Lean `have h' := f h` | ✓ |

| 改写 | Isabelle `subst`：只换一处（`subst (2)` 选第几处） | ≈ 遍历次序写成「从外往里、从左往右」；Lean 的 `rw` 会换掉所有相同的出现，要在关后点明 |
| 化简 | Isabelle `simp only`、Lean `simp only`：改到改不动 | ≈ 真实的 simp 由里往外改，规则次序不由用户排；「会绕圈的化简」已经说明有序重写 |
| 「先后」（第 10 章，规则排列次序改变结果） | 无：真实 simp 的结果不取决于用户列出规则的次序 | ✗ 这一课是这里发明的语义 |
| 已知里的等式 | Isabelle `subst h`、`simp add: h`；Lean `rw [h]` | ✓ |

## 6. 引擎：复用什么，补什么

**已有（`games/kit/domains/logic/`）：** 公式（`formula.js`）、证明板与规则（`proof.js`，含证出的引理当规则）、证明项与写证明项板（`pterm.js`、`termTree.js`、`ui/TermScreen.jsx`）、拼公式板（`formulaTree.js`、`ui/FormulaScreen.jsx`，界面是共用的 `kit/strip`）和造世界板（`fol.js`、`ui/WorldScreens.jsx`）、机器板（`machine.js`：等式组、证明状态、证明项、子句；重复框、几条路、每个目标、搜到证完）、带元变量的规则与合一（`schematic.js`）、证明状态与策略（`tactics.js`）、子句与归结（`resolution.js`：子句集、归结、饱和、证书、重放；一阶的先合一）、改写与化简（`rewrite.js`）、结构化脚本与写脚本板（`script.js`、`ui/ScriptScreen.jsx`）、类型声明给的规则（`datatype.js`）、卡片选项（`choices.js`）；kit 的步进回放（`engine/trace.js`、`shell/usePlayback.jsx`）。

**诚实的限制：**

- 不做完整的高阶合一，只做 Miller 模式；Lean 的展开只取「合一解隐式参数」这一点。
- 项是一阶的：没有以函数为参数的项，所以递推子和终止度量（`termination`、`decreasing_by`）不在板上做，只在点题和百科里讲；终止的必要用「停不下来的定义推出矛盾」来讲。
- 依赖类型只做到向量这一级，向量写成只记长度的命题 `Vec(n)`；不做宇宙层级和归纳族的一般理论，点题里说明。
- 自动化是归结加因子化和包含删除，重放一步一步查证书（每一步是一次归结或取一个样子）；∃ 在 ∀ 底下的 Skolem 函数要选择公理，重放不做；`blast` 的表证明、`omega` 这类判定过程只在点题里出现。反射只做命题公式（两个字母的真值表）。
- 脚本是选出来的行，不是解析文本：have、show、assume、fix、obtain 和 proof … qed，没有 `calc` 和按情况分的块。
