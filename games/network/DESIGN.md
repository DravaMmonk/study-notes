# 《从一根线开始》（计算机网络）设计框架

工作名《从一根线开始》（From One Wire），专题是计算机网络：从一根会出错的线，一层层搭到今天的互联网。所有类图灵完备游戏共同遵守的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；本文档只记录这个专题自己的内容。现在是框架阶段：第 0–1 代写到逐关，后面几代写到系列；逐关的规格等引擎原型做出来再写。

**学习者：** 不假设任何 IT 基础。比特、二进制数、字符编码、"协议"这个词，都在游戏里从头讲起。

**终点：** 学完以后，学习者在模拟世界里打开一个网页，跑的全是自己搭的东西：网卡、交换机、路由器、路由协议、可靠传输、拥塞控制、DNS 解析器、HTTP、TLS、QUIC。看一次网页加载时，能看见每一层在做什么：哪一帧在哪根线上、哪张表查了哪一行、哪个包丢了又是谁补发的。

## 1. 映射：把《图灵完备》搬到网络上

| 《图灵完备》 / 已有几款 | 从一根线开始 |
|---|---|
| 原件 NAND | **一根会出错的线**，加上几个极小的元件（选择、比较、算术、异或、拼接与截取）。线路本身的物理（电平、调制、时钟恢复）交给世界，不教；从"线上能送 0 和 1，但会晚到、会出错"这一层起步 |
| 搭好的电路变成元件 | 搭出的板变成元件：成帧器、CRC、网卡、交换机、路由器、TCP、解析器……后面的关直接用；整台网卡、整台交换机也是元件，摆到拓扑上 |
| 测试 | 给定一张拓扑（节点、线路和线路的延迟、带宽、出错率）和一组要送的东西，检查到达的内容、顺序和时间；带随机的关在多个种子下各跑一遍 |
| 失败给出那一组 | **时序图**：每个节点一条泳道，帧在泳道之间斜着走，标出出错的那一帧和原因（"这一帧的第 37 位在线上翻了，CRC 没查出来"；"两台交换机之间这一帧转了 400 圈"） |
| 元件数 / 计算量 | **延迟、吞吐、多发了多少字节**。约束挑战靠它（"这条长线上吞吐不低于带宽的 90%"逼出滑动窗口） |
| 机体 | 学习者搭的那张网。每一代多一种节点或多一层能力，都是同一张网在长大，每一代 `keeps: 'all'` |

**要练出的思维：** 双方必须事先约好格式；线是不可靠的，出错是常态；一层只信下一层承诺的那一点；能在端上做的就别放在网中间（端到端原则）；地址要分层，表才放得下；大家共用的东西（一根线、一个瓶颈）要靠每个人自觉退让；名字和地址是两回事；路上的每一个人都看得见你说的话。

## 2. 核心机制

### 2.1 一台逐拍的机器

整个游戏只有一种跑法：世界按拍推进，每一拍，每个节点跑一遍自己的板，读这一拍各个端口上的东西，写这一拍要发的东西；跨拍的值存在**寄存卡**里（和《一切皆文件》第 1 代一样）。共享引擎的 `walk` 几乎能直接用：每一步是（拍，节点）。学习者单步运行时，看到的永远是"这一拍，网里每一处发生了什么"。

一拍送什么，随换代变粗：

- **第 0–1 代，一拍一个比特。** 端口上读到 0、1，或"线上没信号"。按位的循环就是时间本身：CRC 每拍移一位，就是真实网卡里的移位寄存器。
- **第 2 代起，一拍送一段。** 学习者把第 1 代的整套收发电路收成「网卡」，线的两头从此各是一块网卡：一帧按自己的长度和线的带宽占线若干拍（发送时间），过了线的延迟，在最后一位到达的那一拍整帧出现在收方的端口上。帧在线上一拍一拍地往前走，时序图和拓扑图上看得见它占了多长一段线。

不改成"一件事来了才跑"（离散事件）的理由：

- **撞车自然出现。** 总线上两帧在同一拍重叠就坏了；"先听再说"就是读"这一拍线上有没有信号"。用事件模拟要专门造重叠的判定，逐拍里它就是世界本来的样子。
- **计时器由学习者自己搭。** 寄存卡加算术就是倒数的计数器（第 2 代「撞了等一会」里第一次搭出**计时器**），不必作为机体能力发下来，原始元件又少一件。
- **一拍就是一个能看清的瞬间。** 排队、超时、拥塞窗口的增减，都落在可以单步的拍上。

代价是空转：没有事的拍，每个节点照样跑一遍板。引擎可以跳过输入和寄存卡都没变的节点；回放时把连续的空拍并成一段快进。后几代一次传输要几千拍时，靠快进看整体、靠单步看要紧的那几拍。

### 2.2 循环

逐拍跑的时候，跨拍的重复就是时间。第 2 代起整帧在一拍里到达，要在这一拍之内扫过一串东西（把报头的每个 16 位字加起来、按前缀长度从长到短查表、Dijkstra 每轮取最近的点），这时引入**重复框**：区域里的电路一圈一圈跑，直到条件满足。它第一次出现在 IP 报头校验和（第 3 代），引言接在第 1 代"逐拍加起来"的经验上。重复框现在在 `domains/logic`（《证明完毕》的化简器），领域之间不互相依赖，所以要先把它挪进 kit 成为共用的框。

### 2.3 数据的样子

- **比特**、**比特串**、**数**（固定位宽）。
- **帧**：一段比特串。按字段拆开它的，是学习者用截取搭出的解析器（拆以太帧头、拆 IP 头、拆 TCP 头……每种报头一个封装件），不提供"按格式拆"的设置项：那是藏起来的组合（手册第 1 节「基础元件保持最少」）。每种报头搭一次，就是一道换外观的练习。
- 视图：比特串按字段着色（字段名来自学习者的解析器），表按行画（转发表、ARP 表、路由表、连接表）。

### 2.4 世界

- **拓扑**：节点和线路，由关卡给定。点对点的线，或一根大家都挂在上面的总线（第 2 代）。
- **线路的旋钮**：延迟、带宽、出错率（翻比特、丢帧）、乱序（多条路径时）、容量（队列满了就丢）。都由关卡定，测试换着种子跑。
- **对抗信道**：除了随机出错，关卡可以写一条"恰好"的出错（翻掉恰好两位、恰好丢第三个确认），作为隐藏测试，保证 naive 解一定被抓到（同《一切皆文件》的已知出错时间线）。

### 2.5 视图

- **时序图**：每个节点一条泳道，时间往下走，帧画成斜线（斜率就是延迟，粗细就是发送时间）。整个游戏最核心的视图，从第 1 代的"晚到"起一直用。
- **拓扑图**：帧在线上移动，队列里排着几帧，表里刚查了哪一行。
- **帧视图**：按字段着色的比特串；出错的位标红。
- **曲线**：拥塞窗口、队列长度、吞吐随时间变化（第 6 代）。

## 3. 原始元件

尽量少，都属于网络本身。每一个都问过"能不能用已有的接出来"。

| 元件 | 做什么 | 第一次出现 |
|---|---|---|
| 选择 | 条件为是取一路，否则取另一路 | 1 |
| 比较 | 相等；后来添「小于」形状 | 1 |
| 算术 | 加一、相加；后来添「相减」「取模」，第 9 代添「相乘」形状 | 1 |
| 异或 | 两个比特（后来两个等长比特串）逐位异或 | 1（奇偶校验） |
| 拼接 / 截取 | 把几段比特串接起来；取出从第 i 位起的 n 位 | 1（成帧） |
| 随机数 | 给出一个随机数（带种子） | 2（退避） |
| 队列 | 有容量的先进先出；满了说"丢了" | 2（交换机） |
| 表 | 按键查、写、删 | 2（自学习交换机） |

**机体能力**（不是元件，由地基关教）：寄存卡、逐拍发收比特（第 1 代）；整帧收发、多端口（第 2 代）；重复框（第 3 代）。

**不作为原始元件的**（都由学习者搭出）：非、与、或（选择接出）；移位发送、按字节收；成帧器、CRC；退避；计时器；最长前缀匹配；Dijkstra；滑动窗口；RTT 估计；DNS 解析；模幂；哈希（玩具版）。

| 0 | 纸笔 | 手写比特 | — | — |
| 1 | 一根线 | 逐拍发收、寄存卡 | — | 数据里正好有旗标 |
| 2 | 局域网 | 整帧、多端口；随机数、队列、表 | 一栋楼的网 | 环里的广播 |
| 3 | 网际 | 重复框 | 跨三个网送一封信 | 两种 MTU |
| 4 | 自己算路 | 节点之间交换路由信息 | 断一根线，网自己好 | 计数到无穷 |
| 5 | 端到端 | 主机上的多个程序 | 自己的 TCP | 序号绕回来 |
| 6 | 拥挤 | 多条流共享瓶颈 | 十条流分一根线 | 缓冲越大越慢 |
| 7 | 地址 | 开机时什么都不知道的主机 | 一个家庭网络 | 从外面连进来 |
| 8 | 名字 | 名字 | 自己的解析器 | 被投毒的缓存 |

### 第 0 代 · 纸笔

还没有机器，学习者手写。

| 关 | 名称 | 新东西 |
|---|---|---|
| 0-1 | 只能说两个字 | 一根线上只分得出两种状态，记作 0 和 1；约好"0 是不，1 是是" |
| 0-2 | 数怎么说 | 二进制数：每多一位，能说的数翻倍；固定位宽 |
| 0-3 | 字怎么说 | 一张对照表把字母变成 8 位（类 ASCII）；双方必须用同一张表 |
| 0-4 | 先说多长 | 一串比特没有标点：先用 8 位说长度，再说内容。这就是第一个协议 |

### 第 1 代 · 一根线

**能力：** 一根点对点的线，每拍送一个比特，有延迟；两头的节点每拍跑一遍板；寄存卡。从「线会出错」那一关起，线会翻比特。

**地基与练习**（新机制和它的练习交替；括号里是产出的封装件）

| 关 | 名称 | 新东西 / 变化的维度 |
|---|---|---|
| 1-1 | 传话 | 逐拍：中间的节点把左边收到的发到右边 |
| 1-2 | 晚到 | 机关台：线的长度、带宽、一段话的长短三个旋钮，看时序图里一段话从开始发到收完要多久（传播时间和发送时间） |
| 1-3 | 一位一位地发 | 寄存卡数拍，每拍发出一个字节的下一位（**移位发送**） |
| 1-4 | 一位一位地收 | 攒满 8 位交出一个字节（**按字节收**） |
| 1-5 | 从哪开始 | 线上没话时一直是 0，对方什么时候开始说？起始位 |
| 1-6 | 起止位 | 练习·组合：连发几个字节，每个带起始位和停止位 |
| 1-7 | 在哪结束 | 长度前缀（第 0 代手做过的，现在搭成电路）；和旗标 + 位填充两条路，并行组 |
| 1-8 | 旗标 | 01111110 夹住一帧；内容里连着五个 1 就塞一个 0（**成帧器**、**拆帧器**） |
| 1-9 | 一帧接一帧 | 练习·加层数：背靠背的几帧、空帧 |
| 1-10 | 线会出错 | 世界开始翻比特；收到的错了却不知道。奇偶校验（只是一课：CRC 出来后再没人用，不做成元件） |
| 1-11 | 错了两位 | 练习·辨真伪：恰好翻两位，奇偶查不出来 |
| 1-12 | 二进制长除法 | 手算：一串比特除以一个生成式，余数就是校验码（不进位的除法就是异或） |
| 1-13 | 边收边除 | 逐拍：寄存卡里的几位就是除到一半的余数，每拍移一位、按需异或（**CRC**） |
| 1-14 | 一串错 | 练习·换外观：连续翻掉几位（突发错误），CRC 查得出，求和查不出；机关台换生成式 |
| 1-15 | 坏帧扔掉 | 组合：成帧 + CRC，收到坏帧就丢（这一层只负责查出来，不负责补发：理由在第 5 代兑现） |

**主线收尾：一块网卡**（命名系列，同一个问题在长大，最后一关造出网卡）

| 关 | 加回的机制 | 产出 |
|---|---|---|
| N1 送一句话 | 移位发送 + 按字节收，线不出错 | — |
| N2 送几句话 | 成帧 | — |
| N3 线会出错 | CRC，坏帧丢掉 | — |
| N4 一块网卡（终极） | 收发两半装成一个元件：上面交给它整帧，下面是比特 | **网卡** |

它在主线上而不是专题：第 2 代的线建在网卡上，主线不能依赖可选专题搭出的元件。这一代没有专题。

**挑战：** 数据里正好有旗标（naive 解：只用旗标不做位填充，内容里出现 01111110 时帧被切断）。

### 第 2 代 · 局域网

**换代：** 线的两头各是一块网卡，一拍送一段，整帧到达（第 2.1 节）。节点照样每拍跑一遍板。引言说上一台机器为什么不够：两个人可以，三个人怎么办？

**新的外部能力：** 一根总线上挂好几个节点（每个都收得到每一帧，也读得到这一拍线上有没有信号）；多端口的节点（「交换」系列起）。

| 系列 | 关 | 新东西 |
|---|---|---|
| 地址 | 都听得见 / 只收给我的 / 广播 | 帧头里写收件人和寄件人；按地址过滤（**拆以太帧头**）；全 1 地址给所有人 |
| 撞车 | 同时开口 / 先听再说 / 撞了等一会 / 越撞等越久 | 两帧在同一拍重叠就都坏了；先听这一拍线上有没有信号；随机数：撞了随机等几拍，用寄存卡倒数（**计时器**）；再撞等待加倍（**以太网卡**） |
| 有多快 | 机关台 | 站的数量、负载两个旋钮，比较"想说就说"、"先听再说"的吞吐 |
| 交换 | 一人一根线 / 先存再转 / 不知道就喊 / 记住谁在哪 / 忘掉旧的 | 集线器只是把总线缩成一个点（还会撞）；队列：存下整帧再转发；不知道收件人在哪就发到所有端口；表：从寄件人地址学到它在哪个端口；用计时器让表项过期（**交换机**） |
| 环 | 绕圈的帧 / 选一个根 / 量离根多远 / 堵上多余的口 | 两台交换机连成环，广播永远转下去；生成树：最小编号当根，每台记到根的距离，只留最近的那条路（**生成树交换机**） |

每个系列后面跟练习：换拓扑（树、环、两层）、加层数（多台交换机）、去支架（站多到表放不下）、辨真伪（看起来没有环、其实有）。「撞车」和「交换」互不依赖（交换不需要退避），排成并行组；「环」需要「交换」。

**专题：一栋楼的网**（三层楼，每层一台交换机，楼层之间有冗余的线；终极：随便拔一根线，网还通）。

**挑战：** 环里的广播（一个看起来是树、其实楼上楼下多接了一根的拓扑；naive 解：不跑生成树的交换机）。

### 第 3 代 · 网际

**墙：** 把所有交换机连成一张大网：每台交换机的表要记下全世界每一台机器；广播传遍全世界。

| 系列 | 新东西 |
|---|---|
| 分层的地址 | 手做：一个地址分成"哪个网 + 网里的哪台"；前缀长度 |
| 路由器 | 按目的网络转发（表：前缀 → 端口），不再按每台机器 |
| 报头校验 | 一帧整个到达，要把报头每 16 位加起来：先手展开固定长度的，再碰上变长报头，引入**重复框**（**IP 校验和**，复用第 1 代"边收边加"的想法） |
| 最长前缀 | 几条前缀都匹配时取最长的：重复框从长到短试（**最长前缀匹配**） |
| 找邻居的地址 | 知道对方的网际地址，不知道它的网卡地址：广播问一声，记下来（**ARP**） |
| 转圈的包 | 两台路由器的表互相指着对方；每过一跳减一，减到 0 就扔掉并告诉发件人（TTL、ICMP）；练习：用它量出一条路上有几跳（traceroute） |
| 太大了 | 一段线允许的帧比另一段小：切片和重组（这一系列可选，挂在路由器之后） |

**专题：跨三个网送一封信**（三个局域网、两台路由器；终极：表由学习者手填，任意两台机器能互通）。

**挑战：** 两种 MTU（中间一段线更小，naive 解：不切片，大包全丢）。

### 第 4 代 · 自己算路

**墙：** 表是手填的。断一根线，手填的表就把包送进死路；网大了没人填得过来。

两路并行（互不依赖）：

- **距离向量**：每台路由器只告诉邻居"我到各处多远"；邻居收到就加一跳，取最近的。墙：断线后两台路由器互相以为对方能到，距离一路加上去（计数到无穷）；水平分割、毒性逆转。
- **链路状态**：每台路由器把自己的邻居和线路花费洪泛给所有人（复用交换机的泛洪，加上序号防止旧消息转圈）；每台各自用 Dijkstra 算出到各处的最短路（重复框 + 取最小，**Dijkstra**）。

两路合流后：

- **自治系统之间**：一张网由很多家各自管理；不只看远近，还看愿不愿意（策略）；带着走过的路一起传，看到自己在路上就丢（路径向量，BGP 的骨架）。

**专题：断一根线，网自己好**（终极：随机断线，测路由收敛前后丢了多少包）。

**挑战：** 计数到无穷（naive 解：没有水平分割的距离向量）。

### 第 5 代 · 端到端

**墙：** 网际只尽力而为：包会丢（队列满了）、会乱序（两条路）、会重复、会晚到。网中间不负责补发，第 1-15 关留下的"只查不补"在这里兑现（端到端原则：只有两头知道一段话完整没有）。

| 系列 | 新东西 |
|---|---|
| 门牌 | 一台主机上几个程序：端口号（**数据报**，UDP 的骨架） |
| 停一停等一等 | 发一个、等确认、超时重发；确认丢了会重复收到 → 序号（**停等**） |
| 太慢了 | 机关台：线越长、带宽越大，停等越浪费（带宽 × 延迟）；滑动窗口：回退 N、选择重传（**滑动窗口**） |
| 等多久 | 超时太短白重发，太长干等；用估计的往返时间和它的抖动定超时（**RTT 估计**） |
| 别把对方淹了 | 收方告诉发方自己还能收多少（流量控制） |
| 打招呼 | 三次握手（为什么两次不够：旧连接的迟到的包）；四次挥手和等待（**连接**） |
| 字节流 | 没有消息边界：一段话可能分几次到，也可能几段一起到；在上面分帧（复用第 1 代的长度前缀想法） |

**专题：自己的 TCP**（终极：在丢包、乱序、重复的网上可靠地送一个大文件）。

**挑战：** 序号绕回来（窗口比序号空间的一半大时，新旧分不清；naive 解：窗口开满序号空间）。

### 第 6 代 · 拥挤

**墙：** 十条可靠的流挤过一根瓶颈线：每条都尽量快发，队列满、丢包、重发、再丢，吞吐反而塌下去（拥塞崩溃）。

| 系列 | 新东西 |
|---|---|
| 一起退让 | 机关台：两条流的发送速率画在一张图上，看"加法增、乘法减"怎么收到公平的那一点（AIMD） |
| 拥塞窗口 | 发方自己估一个窗口；丢包就减半 |
| 起步 | 从一个开始，每个往返翻倍（慢启动）；阈值 |
| 三个重复确认 | 不等超时：连收三个同样的确认就重发（快重传、快恢复） |
| 队列也要管 | 队列太大让所有人都慢（缓冲膨胀）；提前随机丢、或者打个标记（RED、ECN） |

练习看曲线：拥塞窗口的锯齿、多条流的公平、长线和短线争同一个瓶颈。

**专题：十条流分一根线**（终极：吞吐、公平、队列延迟三个指标同时达标）。

**挑战：** 缓冲越大越慢（naive 解：把瓶颈的队列开到很大）。

### 第 7 代 · 地址

**墙：** 新插上的主机不知道自己的地址、路由器在哪；地址不够分。

- **开机问地址**：广播一声，服务器分一个地址给它，带期限（DHCP）。
- **一个地址很多人用**：家里的路由器把内部的地址和端口改写成自己的，记一张对照表（NAT）；练习：几台主机同时出门、对照表过期。
- （可选）**更长的地址**：IPv6 的地址够每台机器一个，主机自己拼出地址。

**专题：一个家庭网络**（终极：几台设备开机、拿地址、通过一台家用路由器上网）。

**挑战：** 从外面连进来（NAT 后面的服务器收不到连接；跳跃：端口转发，或两边同时往外打洞）。

### 第 8 代 · 名字

**墙：** 人记不住地址；地址会变。一张"名字 → 地址"的大表放不下、改不过来。

- **一张表** → **分层**（根、顶级域、各家自己的服务器，各管一段）→ **一步步问**（解析器从根问起）→ **记住答案**（缓存和它的有效期）→ **问不到也记住**（否定缓存）。
- 搭出 **解析器**。

**专题：自己的解析器**（终极：在一张有几十个名字、几层委派的世界里，解析器问的次数不超过预算）。

**挑战：** 被投毒的缓存（攻击者抢在真答案前塞一个假答案；naive 解：编号固定的查询；跳跃：随机的查询编号和端口）。

### 第 9 代 · 网页

**墙：** 网通了，但两个程序要"说同一种话"：请求什么、回什么、多长。

- **一问一答**：文本的请求行和状态行（复用第 0 代的字符表）、报头。
- **多长**：长度报头，或者分块（又一次成帧，接第 1 代和第 5 代）。
- **一条连接多问几次**（持久连接）。
- **没有记性的协议**：Cookie。
- **别每次都拿**：缓存、条件请求（ETag）；代理。

**专题：一个能浏览的小网**（几台服务器、几张互相链接的页面；终极：一个浏览器从名字开始，经解析、连接、请求，拿到一张页面和它引用的东西）。

**挑战：** 一个慢响应堵住全部（一条连接上前一个响应慢，后面的全等着；naive 解：所有请求排在一条连接上）。

### 第 10 代 · 保密

**墙：** 路上的每一个人都看得见（学习者在第 2 代搭的总线和交换机的泛洪，就能看见别人的帧）；也改得了。

| 系列 | 新东西 |
|---|---|
| 藏起来 | 用一串只有双方知道的随机比特异或（复用第 1 代的异或）；同一串用两次就露馅（练习·辨真伪） |
| 怎么约好钥匙 | 在大家都看得见的线上约出只有两人知道的数：算术添「相乘」形状，重复框搭出模幂（**模幂**），Diffie–Hellman |
| 你是谁 | 中间人分别和两边约钥匙；公钥签名（玩具版 RSA） |
| 谁担保 | 证书：一个大家都信的人签过"这把公钥是这个名字的"；证书链 |
| 没被改过 | 玩具哈希和消息认证码；重放和随机数 |
| 合起来 | 握手：约钥匙、验证书、之后的每一帧加密加认证（**TLS**） |

**专题：自己的 TLS**（终极：在有窃听者和篡改者的网上，浏览器和服务器建立安全连接，测试检查窃听者拿不到内容、篡改都被发现）。

**挑战：** 中间人（naive 解：只做 Diffie–Hellman，不验证书）。

**诚实的限制：** 这里的密码学都是小数字的玩具版，原理是对的，强度不是。引言和百科里要明说：真实系统用的是经过审查的算法和实现，不能照着游戏里的做法自己写。

### 第 11 代 · 现代

**墙：** 第 9 代的挑战留下的问题：一条连接上排队。

- **一条连接里多条流**：给每条流编号，帧交错发送（HTTP/2，又一次成帧）。
- **丢一个包，所有流都停**：TCP 只有一条字节流，丢包时后面所有流都等（传输层的队头阻塞）。
- **在 UDP 上重做传输**：每条流各自可靠、各自有序，握手和 TLS 合在一起少一个往返，连接用编号认而不是用地址认（QUIC）。复用第 5、6、10 代的元件。
- （可选）**离用户近一点**：同一个地址在很多地方宣告，BGP 把用户送到最近的那一个（任播、CDN），复用第 4 代。

**专题：打开一个网页**（全书终点。一台新插上的笔记本：拿地址、问路由器的网卡地址、解析名字、建立 QUIC 连接、握手、拿页面。每一步跑的都是学习者自己搭的元件；时序图从最底下的帧画到最上面的请求）。

**挑战：** 换了网络连接不断（笔记本从一个网换到另一个，地址变了；naive 解：按地址认连接的 TCP）。

## 5. 元件从哪里来

- **原始元件**：第 3 节那张表，八个。
- **机体能力**（地基里教）：逐拍发收、寄存卡；整帧收发、多端口；重复框。
- **学习者造的封装件**：移位发送、按字节收、成帧器、拆帧器、CRC、网卡、拆以太帧头、以太网卡、交换机、生成树交换机、IP 校验和、最长前缀匹配、ARP、路由器、Dijkstra、数据报、停等、滑动窗口、RTT 估计、连接、TCP、解析器、模幂、TLS……每个都要在后面的参考解里用到（审计 `unused`）。
- **整台节点也是封装件**：网卡、交换机、路由器、主机的协议栈都是一块板，摆到拓扑的节点上。后面几代的拓扑上，节点默认装着学习者自己搭的那一台。

**抽象链要检查的几处**（手册第 7 节第 5 步）：

- 成帧在第 1、5、9、11 代各出现一次（旗标、字节流上的长度前缀、HTTP 的长度和分块、HTTP/2 的帧），后面几次要用前面搭出的元件，而不是从截取重搭。
- 泛洪在交换机、链路状态、（可选）DNS 的区传送里复用。
- 第 11 代的参考解几乎只用高层元件；如果它还在用原始元件，说明中间哪一层没进抽象链。

## 6. 引擎：复用什么，补什么

新领域 `games/kit/domains/net/`。

**能直接复用的：** 电路编辑器、外壳、课程审计；`engine/machine.js` 的 `walk`（逐拍机：每一步是一个（拍，节点））；寄存卡的做法（`domains/unix/lines.js`）；`usePlayback` 的步进。

**要新做的（按顺序）：**

1. **逐拍机和一根线**：线路的延迟、带宽和带种子的翻比特；时序图视图。第 0–1 代只需要这些。
2. **整帧的线**：帧按长度和带宽占线若干拍、过延迟后整帧到达；总线上同一拍重叠的帧都坏掉，每个节点读得到"这一拍线上有没有信号"。拓扑世界和拓扑视图；跳过没变化的节点，回放时把空拍并成快进。
3. **网卡收进线里**：第 2 代起线上送整帧，等于线的两头各装着学习者的网卡；每一帧都逐位跑网卡电路会很慢，所以线路默认按网卡的行为直接送帧，`npm run check` 对照学习者搭网卡的那一关验证两者一致（手册第 5 节"黑盒与搭出它的那一关一致"）；点开一条线，可以切到逐拍回放其中某一帧。这是对"封装件跑学习者的电路"的一处例外，要在原型里看玩家能不能接受。
4. **重复框**挪进 kit 共用。
5. **队列、表的视图**；曲线视图（第 6 代）；代价度量（延迟、吞吐、多发的字节数）。

**模拟的分寸：** 目标是把网络的工作机制和原理讲清楚，不是复现真实协议栈的每一个细节，所以不做和真机逐项对照的一致性检查。要守住的是：

- **现象要出现，而且出现在对的原因上。** 拥塞窗口的锯齿、多条流趋向公平、缓冲过大时延迟上升、计数到无穷，都要由学习者的参考解在模拟里真的跑出来；`npm run check` 检查这些现象（比如"两条流的吞吐比在 1.5 以内"），不检查具体数值。
- **简化要说出来。** 每一处和真实协议不同的地方（报头字段删减、序号位宽缩小、只有一种拥塞算法），在百科对应的词条里写一句"真实的 X 还会……"，不让学习者把简化版当成真的。
- 便宜就顺手做对的：CRC、校验和按真实算法算，不另设对照测试。

**诚实的限制：**

- 物理层（编码、调制、时钟恢复）整个不讲：线从"能送比特"开始。以后可以加一条可选支线，打开线路元件看里面的电平和时钟。
- 排队和丢包模型很粗；第 6 代讲的是拥塞控制的原理，曲线的具体形状不代表真实网络。
- 密码学是玩具版（见第 10 代）。
- 全程逐拍会有大量空转：后几代一次传输要几千拍。跳过不变的节点、快进空拍能不能撑住手机浏览器，要在原型里量。

## 7. 建议的第一步

1. 先做第 0–1 代：逐拍机几乎就是现有的 `walk`，能最早上线，也能验证"时序图 + 逐拍电路"这种玩法零基础玩家能不能上手。
2. 紧接着做第 2 代"地址"和"撞车"两个系列的原型：整帧的线、网卡收进线里、几千拍的回放是风险最大的三件事，要在写后面几代的逐关规格之前试出来。
