## 1. YOLO：整图一次预测类别和框

![PDF 6 - YOLO v1](assets/22-object-detection-ii/slide-06.png)

沿网络从左向右看：整张图的特征最终变成网格上的类别分数和框参数。YOLO v1 不先提出一批候选区域再逐框分类，而是直接预测这些输出。右侧的“20 类、2 个框”属于图中版本和设置，不是所有 YOLO 的固定配置。

一个框除了中心位置、宽高，还带有置信分数。网格位置负责预测中心落在相应区域的物体；多个物体挤在小区域中时，有限的网格和框数会限制表达能力。课件讨论的是早期 YOLO v1，不能把它的精度与速度结论直接套到所有后续版本。

<a id="topic-2"></a>
## 2. 难点：DETR 为什么把检测看成集合预测

DETR（Detection Transformer）的输出是一组“类别 + 框”。物体的排列顺序不重要：先写左边的马还是右边的马，都应表示同一个检测结果。

![PDF 11 - DETR encoder and decoder](assets/22-object-detection-ii/slide-11.png)

从左到右看：CNN 提取图像特征，Transformer 编码器让各位置交换信息；解码器把这些图像信息与一组 **object queries（物体查询）** 结合，最后每个查询对应一个类别和一个框。

可以把查询理解成可学习的“输出槽位”。它不是用户输入的文字问题，也不等于预先画好的候选框。课件以 $N=100$ 个槽位为例：图中物体少于 $N$ 时，多余槽位应输出 **no object（没有物体）**。这里的 $N$ 是最多可以输出多少个检测，不表示每张图都有 100 个物体。

### 一对一匹配：先配对，再计算训练误差

![PDF 13 - Set prediction matching](assets/22-object-detection-ii/slide-13.png)

左列是真实物体，右列是预测结果；箭头跨行连接，说明不能直接把“第一行预测”当成“第一行答案”。训练先综合类别和框的位置寻找整组的一对一配对，再对配对结果计算损失。未分配给真实物体的槽位学习输出 no object，其损失权重较低。

**易错**：同一匹马不能让多个预测都算作正确配对。一对一训练让模型学习输出不重复的集合，所以这里介绍的原始 DETR 通常不再依靠 NMS 删除重复框。这不表示网络永远不会误检或漏检。

| 方法 | 怎样组织预测 | 主要区别 |
| --- | --- | --- |
| Faster R-CNN | 候选区域 → 分类与框修正 | 两阶段，见 [上一讲](21-object-detection-i.md#topic-3) |
| YOLO v1 | 网格上的类别与框参数 | 直接预测，但可能产生重复框 |
| DETR | 一组查询槽位 → 类别与框 | 集合预测，一对一匹配训练 |

<a id="topic-3"></a>
## 3. NMS：删掉重复报告同一物体的框

![PDF 19 - Duplicate detections](assets/22-object-detection-ii/slide-19.png)

蓝框和橙框覆盖左边同一只狗，IoU 为 0.78；右边狗的框与蓝框重合很小。以课件示例的 0.7 阈值为例：保留最高分蓝框 0.9，再抑制与它高度重叠的低分橙框 0.8，然后在剩余框中继续选择。

这就是非极大值抑制 NMS，通常按类别分别做。它比较的是**预测框与预测框**，不需要真实答案框。不同物体也可能高度重叠，因此 NMS 在拥挤场景中可能误删正确检测。

<a id="topic-4"></a>
## 4. AP 与 mAP：排序、类别和位置都要检查

对一个类别，把测试集检测按分数从高到低排序，再用指定 IoU 阈值与同类真实框匹配。一个真实物体只能被成功匹配一次；额外重复检测计为错误，而不是重复加分。逐步纳入低分检测时计算：

$$
\mathrm{Precision}=\frac{TP}{TP+FP},\qquad
\mathrm{Recall}=\frac{TP}{N_{\mathrm{GT}}}.
$$

$TP$ 是正确匹配的检测数， $FP$ 是错误检测数， $N_{\mathrm{GT}}$ 是真实物体数。Precision 问“报出的有多少是对的”，Recall 问“实际存在的找到了多少”。沿排序逐步计算，得到 P–R 曲线；AP 总结单类的曲线面积，具体插值规则以评价协议为准。

![PDF 34 - Class and IoU averaging](assets/22-object-detection-ii/slide-34.png)

图中的鸟、猫、狗 AP 分别是 0.65、0.80、0.86，按类别平均得到 mAP@0.5 = 0.77。COCO mAP 还对从 0.50 到 0.95、间隔 0.05 的多个 IoU 阈值取平均；更严格的阈值要求框贴得更准，所以不能把两种分数直接比较。

**易错**：NMS 的 IoU 阈值决定删掉哪些预测框；评价的 IoU 阈值决定预测框与真实框能否算匹配。两者用途不同，不必取同一个值。
