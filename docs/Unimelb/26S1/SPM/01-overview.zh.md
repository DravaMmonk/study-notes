# 1 概述

---

**业务驱动的 IT**
## 什么是项目

- 周期：临时性的工作（有开始也有结束）
- 团队：跨职能；规模可变
- 不确定性：要应对未知
- 产出：独特的；会带来变化

## 组织为什么使用项目

- 在创造新事物时
- 让关键活动与交付物保持一致，并明确如何确定它们的优先级
- 便于（为业务）进行结构化和正式化
- 便于控制有限的资源
- 确立归属、共识和问责

## 项目管理 = 权衡

- 项目管理三角 (Project Management Triangle)：**资源、范围和时间**
- PMI 六约束模型：**范围、时间、成本、质量、风险、资源**

## 项目经理的主要职责

|         | 启动阶段 | 维持阶段     |
| ------- | -------------- | --------------- |
| 项目 | **计划**   | **控制** |
| 团队    | **组织** | **领导**     |

## 项目章程 —— 项目的开端

![[Screenshot 2026-03-09 at 5.12.20 pm.png]]

项目章程 (Project Charter) 是一组文档，说明： 
- 项目目的
	- 商业论证 (business case)
- 项目目标
- 范围（包含与不包含的内容）
- 进度
	- 角色与职责
	- 预算估计
- 主要风险
- 成功标准

当**项目章程获得发起人 (sponsor) 批准**时，项目正式开始

## 软件开发生命周期（SDLC）模型
### 正式 SDLC

- **瀑布模型 (Waterfall)**
- **增量模型 (Incremental)**
- **螺旋模型 (Spiral)**

*何时选择正式模型？*  
- 客户一开始就知道自己想要什么
- 需求稳定、精确且已知
- 预计不会有变更
- 技术和工具已经成熟

### 敏捷 SDLC

- **Scrum**
- **看板 (Kanban)**

*何时选择敏捷模型？*  
- 客户愿意为项目投入时间
- 需求会不断涌现
- 欢迎变更

*何时选择混合模型？*  
- 客户已经建立了规定性的模型
