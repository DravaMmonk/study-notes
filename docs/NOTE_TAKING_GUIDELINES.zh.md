# 笔记撰写规范

## 目的

- 这些笔记是有据可查的学习笔记，而不是随意的总结。
- 每一条事实性陈述都必须能追溯到课程所存储或引用的讲座幻灯片、研讨课（workshop）幻灯片、指定阅读材料或链接的论文。

## 来源标注规则

- 把出处写在 Markdown 注释中，而不是写在可见正文里。
- 使用 `<!-- Sources: ... -->` 形式的 HTML 注释。
- 把注释紧接着放在它所支撑的段落、列表项、公式、表格或列表块之后。
- 默认每个列表项或段落对应一条来源注释。
- 只有当一条来源注释明确覆盖某个紧密关联块中的每一个论断时，才可以让它跟在整个块之后。
- 如果一条陈述综合了多个来源的信息，就在同一条注释中把它们全部列出。

## 可见文本的写作规则

- 直接陈述论断。
- 不要在可见文本中使用转述来源的措辞，例如：
  - `The lecture says...`
  - `The reading argues...`
  - `JM3 notes...`
- 不要在渲染后的 Markdown 中暴露像 `[Sources: ...]` 这样的行内引用。
- 让可见文本聚焦于概念、定义、方法、结果或比较本身。

## 证据边界规则

- 不要添加没有依据的背景知识。
- 除非更强的措辞有明确依据，否则不要把几条来源中的论断合并成一个更强的论断。
- 当讲座和阅读材料表达同一观点时，只有两者都确实被用到时才同时引用。
- 如果某个公式或表格直接来自某张幻灯片或某篇论文，就在该展示块正下方的 Markdown 注释中引用这一来源。

## 可视化规则

- 当表格能改进比较、分类体系（taxonomy）、工作流程或架构总结时，就添加表格。
- 当课程材料以数学方式呈现方法、且公式能实质性地改进笔记时，就添加 LaTeX 公式。
- 公式和表格要像正文一样有来源支撑。
- 不要添加会引入未经陈述的关系的装饰性图示。

## 文件结构规则

- 优先按讲座主题簇组织文件，每个主题簇一个文件，而不是每份原始 PDF 一个文件。
- 从概念本身开始，而不是从对来源的评论开始。
- 使用简短的小节和稳定的标题，以便在课前、辅导课（tutorial）或考试前快速复习。
- 所有 Markdown 注释（来源标注）在两个语言版本中都保持为英文。

## 双语规则

- 每篇笔记都有英文和中文两个版本。最初写成的文件保持为 `X.md`；译文放在旁边，命名为 `X.zh.md`（原文为英文）或 `X.en.md`（原文为中文）。
- 两个版本保持同步：相同的标题、公式、表格、图片、锚点和来源注释，顺序一致。改动其中一个，就要同时改动另一个。
- 链接到另一篇笔记时，指向同一语言的版本（例如从 `X.zh.md` 链接到 `Y.zh.md`；如果 Y 原本用中文写成，则链接到 `Y.md`）。网站和 Fieldnotes 也会自动把读者带到他们选择的语言。
- 中文正文中，技术术语第一次出现时在括号里给出英文。
- 新建课程文件夹时，在 `docs/.sections.json` 中写上它的英文和中文标题。

## 本地材料处理规则

- 课程源文件和外部阅读材料可以存放在本地以供参考。
- 把原始材料存放在被 gitignore 忽略的目录中，例如 `lecture/`、`workshop/`、`tutorial/` 和 `readings/`。
- 除非任务明确要求，否则只提交整理好的 Markdown 笔记。

