# 《一切皆文件》（Linux 开发）设计框架

工作名《一切皆文件》（Everything Is a File），专题是 Linux 系统编程：从字节流到进程、信号、线程和网络。所有类图灵完备游戏共同遵守的结构、规则和自动检查见 [`games/DESIGN.md`](../DESIGN.md)；本文档只记录这个专题自己的内容。现在是框架阶段：逐关的规格等引擎原型做出来再写。

**终点：** 学完以后，学习者用自己造的命令和自己造的 shell，跑起一个能同时服务多个客户端的小网页服务器；看一个程序时，能看见内核眼里的它：一张文件描述符表、一棵进程树、一串系统调用。

---

## 1. 映射：把《图灵完备》搬到 Linux 上

| 《图灵完备》 / 已有两款 | 一切皆文件 |
|---|---|
| 原件 NAND | **系统调用**。read、write、open、fork、exec、pipe、dup2、wait……内核给的就这么多，cat、grep、shell、服务器全都由学习者从它们搭出 |
| 搭好的电路变成元件 | 搭出的程序变成**命令**，放进 /bin，后面的关直接用。第 1 代造的 grep、uniq，到第 3 代被学习者自己造的 shell 跑起来 |
| 测试 | 给定初始的文件系统、标准输入和参数，检查标准输出、退出码和最后的文件系统；并发关在多种调度下各跑一遍 |
| 失败给出那一组 | 输出的第一处不同（逐行对照）；进程卡死时指出"谁在等什么"（比如：读端在等 EOF，但写端还有一个进程开着）；并发出错时给出那条**调度时间线** |
| 元件数 / 计算量 | 系统调用次数。约束挑战靠它（"读 1 MB，系统调用不超过 300 次"逼出缓冲） |
| 故意犯错关 | 忘了关管道写端、先 `2>&1` 再 `>`、`if` 代替 `while` 等条件变量……引擎让错误必然暴露 |
| 机体 | 一台模拟的 Unix。每一代内核多给一类能力：文件、进程、信号、线程、网络（顺序大致就是 Unix 的历史） |

**要练出的思维：** 一切都是字节流、组合小程序、句柄和它指向的东西是两回事、进程是复制出来的、谁持有资源谁负责关、并发下"大多数时候没事"不等于正确、失败是常态（断电、慢客户端、信号来得不是时候）。

## 2. 核心机制

### 2.1 电路板：三种线

kit 的电路是无环的数据流。系统编程本质上是有先后的副作用，所以线分三种：

- **数据线**：一行文字、一段字节、一个数。第 1 代只有它，和《视觉完备》的流水线几乎一样。
- **句柄线**：文件描述符、进程号、套接字。open 输出一根句柄线，read、write、close 吃它。
- **次序线**：每个系统调用元件都有一个"次序入"和一个"次序出"，把有副作用的元件串成先后。数据流里没有次序线的元件（拆字段、比较）随时可算。

这样电路仍然是无环图，kit 的编辑器、求值、手机格位都能用；学习者看到的是"这几件事一定按这个顺序发生"。

### 2.2 循环交给机体

板上没有通用的循环。重复由机体做，和《状态之图》里机器人在每一格上跑同一块板一样：

- 第 1 代：**每读到一行，跑一遍板**；板外有**寄存卡**（跨行保留的值，带初始值）和**收尾板**（读到 EOF 后跑一次）。
- 第 2 代：**每个目录项跑一遍板**；"进子目录"让同一块板在子目录上再跑。
- 第 6 代：**每来一个事件跑一遍板**（事件循环）。

### 2.3 分身：fork 把板分成两路

fork 是一个特殊元件：它下面的板分成"父"和"子"两条泳道，各自接着往下走。父道拿到子进程号，子道知道自己是子。exec 在一条泳道里把剩下的板换成一条命令。手机上两条泳道是格位的两列。

### 2.4 模拟内核

浏览器里一台确定性的小 Unix（JS）：

- 虚拟文件系统：inode、目录、硬链接和软链接、权限、mtime；
- 进程表、每个进程的文件描述符表、共享的"打开文件"（fork 以后父子共享偏移量，这是要教的点）；
- 有容量的管道（写满会阻塞）、信号、进程组；
- 线程、互斥锁、条件变量；回环网络上的套接字；
- **调度器带种子**：同一组输入在多种调度下各跑一遍；并发关再加一个对抗调度（有界地搜索交错），找到出错的那条就画成时间线；
- **故障注入**：在每个系统调用之后"断电"一次（检查文件是否损坏）、把一次 write 拆成几次到达（TCP 不保留消息边界）、注入虚假唤醒。

### 2.5 视图

数据按形状画（沿用《视觉完备》的思路）：文本、十六进制字节、按字段的表。内核状态另有四种视图：文件描述符表、进程树、inode 图（名字 → inode → 数据块）、时间线（每个进程一条泳道，系统调用按时间排）。

### 2.6 通关点题附 C 代码

过关后，点题旁边给出这块板对应的 C 代码（由板生成）。学习者知道真机上同样的事怎么写，但游戏里不要求写代码。

## 3. 课程

| 代 | 机体 | 新的外部能力 | 专题（终极谜题） | 挑战（例） |
|---|---|---|---|---|
| 0 | 纸笔 | 手算字节和偏移 | — | — |
| 1 | 电传 | 标准输入输出、逐行跑板、寄存卡、管道台 | 日志分析 | 不排序也能数 |
| 2 | 磁盘 | 打开文件、目录、链接、权限 | 快照备份 | 断电也不坏 |
| 3 | 分身 | fork、exec、wait、pipe、dup2 | 自己的 shell | 顺序很重要（`2>&1`） |
| 4 | 信号 | 信号、处理函数、进程组 | 进程管家 | 漏掉的孩子 |
| 5 | 多线 | 线程、锁、条件变量 | 线程池 | 哲学家吃饭 |
| 6 | 联网 | 套接字、事件循环 | 网页服务器 | 慢客户端 |

关数估计：3 + 12 + 12 + 12 + 9 + 9 + 10，约 67 关。

### 第 0 代 · 纸笔

| 关 | 名称 | 新东西 |
|---|---|---|
| 0-1 | 一串字节 | 文件就是一串字节；换行也是一个字节 |
| 0-2 | 读到哪了 | 读三次、每次读 4 个字节，手写每次读到什么、偏移到了哪 |
| 0-3 | 读完了 | 读到 0 个字节就是 EOF |

### 第 1 代 · 电传

**能力：** 只有标准输入和标准输出。机体每读到一行跑一遍板，带寄存卡和收尾板。**管道台**：把几条命令的输出接到下一条的输入（这一代由机体替你接，第 3 代你自己接）。

**原始元件**（一关出现一个）：写出、匹配（含子串）、放行闸、拆字段、转成数、加法、比较、排序（整份输入排序，声明为原始元件：在逐行的机体上拼它太琐碎，离开了专题）。

**地基**

| 关 | 名称 | 新东西 | 产出命令 |
|---|---|---|---|
| 1-1 | 回声 | 逐行跑板、写出 | **cat** |
| 1-2 | 只要有的 | 匹配 + 放行闸 | **grep** |
| 1-3 | 数一数 | 寄存卡、收尾板 | **wc -l** |
| 1-4 | 拆开 | 拆字段 | **cut** |
| 1-5 | 排好 | 排序 | **sort** |
| 1-6 | 去掉重复 | 寄存卡存上一行：只去掉相邻的重复 | **uniq** |
| 1-7 | 接起来 | 管道台：把造好的命令接成一条管道 | — |

**练习（按难度）：** 给每行编号、一列求和、找最长的一行、倒着输出（寄存卡存一张表）、`sort | uniq` 才能去掉所有重复（1-6 的点题在这里兑现）。

**专题：日志分析。** 世界：一份网站访问日志。

| 关 | 加回的机制 | 产出命令 |
|---|---|---|
| L1 有几次 404 | grep + wc | — |
| L2 每个 IP 来了几次 | 计数版 uniq：`sort \| uniq -c` | **uniq -c** |
| L3 谁来得最多 | 再按次数排一次，取前几行 | **head** |
| L4 最常来的三个 IP，各自最常看的页面（终极） | 两层分组 | — |

**挑战：** 不排序也能数（寄存卡存一张"IP → 次数"的表，一遍读完；naive 解：直接 uniq -c，没排序时同一个 IP 被分成几段）。

### 第 2 代 · 磁盘

**能力：** open、read、write、close（句柄线）、lseek、stat、列目录（每个目录项跑一遍板，可以进子目录）、link、unlink、rename、权限。

**地基：** 2-1 打开一个文件（自己的 cat file）、2-2 写进去（**cp**）、2-3 跳着读（lseek，**tail -c**）、2-4 一个文件两个名字（硬链接；inode 视图第一次出现）、2-5 搬家只是改名（**mv** = rename）、2-6 目录也是文件（**ls**）、2-7 不让你看（权限）。

**练习：** 目录有多大（**du**，进子目录）、按名字找（**find**）、软链接指向的是名字不是 inode、删了一个名字文件还在。

**专题：快照备份**

| 关 | 加回的机制 |
|---|---|
| B1 整份复制 | 递归复制目录（**cp -r**） |
| B2 只复制改过的 | 比 mtime 和大小 |
| B3 没改的用硬链接 | 新快照里没改的文件指向上一份的 inode |
| B4 每天一份快照（终极） | 七天七份快照，每份看起来都完整，空间只增长改过的部分 |

**挑战：** 断电也不坏（故障注入在每个系统调用之后断电一次，检查文件要么是旧的、要么是新的；naive 解：截断再写，断在中间就只剩一半；跳跃：写临时文件，fsync，再 rename）。删了还在读（打开以后 unlink，读的人照样读完）。

### 第 3 代 · 分身

**能力：** fork（两条泳道）、exec、exit 和 wait（退出码）、pipe、dup2、close。

**地基：** 3-1 分身（fork，父子各打印一行，时间线视图第一次出现）、3-2 换个身体（exec）、3-3 等它结束（wait、退出码）、3-4 换掉输出（dup2，`>`）、3-5 一根水管（pipe 连两个进程）。

**练习：** 共享的偏移（fork 前打开的文件，父子写会交错而不是覆盖）、`&&` 和 `||`（看退出码）、同时跑两条命令再等两个。

**专题：自己的 shell**

| 关 | 加回的机制 |
|---|---|
| H1 跑一条命令 | fork + exec + wait |
| H2 重定向 | `<` 和 `>`：在子道里 dup2 |
| H3 一根管道 | 两个孩子，一根 pipe；父进程要关掉自己手里的两头 |
| H4 任意长的管道 | n 个孩子、n−1 根管道 |
| H5 跑脚本（终极） | shell 逐行读脚本执行，跑通第 1 代的日志分析：用的是你在第 1 代造的命令 |

H3 里忘了关写端，读的那头永远等不到 EOF：引擎报告"所有进程都在等"，并在文件描述符表里标出还开着的写端。这是专题内的反例，不单设关。

**挑战：** 顺序很重要（`cmd > f 2>&1` 和 `cmd 2>&1 > f` 的结果不同；naive 解按字面顺序反着 dup2）。

### 第 4 代 · 信号

**能力：** 信号的默认动作、处理函数、kill、进程组、SIGCHLD、SIGPIPE、非阻塞的 waitpid。

**地基：** 4-1 叫停（SIGINT）、4-2 接住信号（处理函数）、4-3 孩子结束了（SIGCHLD + waitpid）、4-4 一组一起停（进程组：Ctrl-C 停掉整条管道）。

**练习：** 超时运行（**timeout**）、下游先走了（head 退出，上游收到 SIGPIPE 停下）。

**专题：进程管家**

| 关 | 加回的机制 |
|---|---|
| P1 崩了就重启 | SIGCHLD 里重新 fork |
| P2 别重启得太快 | 退避：连续崩溃时等待加倍 |
| P3 好好地停 | 先 SIGTERM，超时再 SIGKILL |
| P4 管三个服务（终极） | 按依赖顺序启动、崩了重启、停的时候反序 |

**挑战：** 漏掉的孩子（两个孩子几乎同时退出，信号合并成一个；naive 解：处理函数里 wait 一次，留下僵尸；跳跃：循环 waitpid WNOHANG 直到没有。对抗调度保证能找出这条时间线）。

### 第 5 代 · 多线

**能力：** 线程（共享内存）、互斥锁、条件变量。每一关的测试在多种调度下跑，对抗调度专找出错的交错。

**地基：** 5-1 两个线程（计数器加一丢了几次：时间线指出交错的那两步）、5-2 上锁、5-3 等一个条件（条件变量；注入虚假唤醒，让 `if` 必然出错，`while` 才对）。

**练习：** 读多写少（读写锁）、只初始化一次。

**专题：线程池**

| 关 | 加回的机制 |
|---|---|
| T1 一个生产者一个消费者 | 一个格子的缓冲 |
| T2 有界缓冲 | 满了等、空了等，两个条件 |
| T3 多个工人 | 多消费者 |
| T4 线程池（终极） | 提交任务、关闭时不丢任务、所有工人都退出 |

**挑战：** 哲学家吃饭（naive 解：每人先拿左边，对抗调度找到死锁；跳跃：给锁定一个全局顺序）。

### 第 6 代 · 联网

**能力：** socket、bind、listen、accept、connect；poll 和事件循环（每来一个事件跑一遍板）。网络是模拟的回环，write 会被拆成几次到达。

**地基：** 6-1 打个电话（客户端，回声）、6-2 接电话（服务器，一个客户端）、6-3 一个接一个（循环服务器）、6-4 同时接很多（每个连接 fork 一次，用上第 3 代）。

**练习：** 消息被拆开了（一条消息分两次到达：按换行或长度前缀分帧）、聊天室（广播给其他人）。

**专题：网页服务器**

| 关 | 加回的机制 |
|---|---|
| W1 回一句固定的话 | 解析请求行，回一个固定响应 |
| W2 按路径发文件 | 用第 2 代的 open、read；找不到回 404 |
| W3 跑一个脚本 | 用第 3 代的 fork、exec、dup2 把脚本输出接回套接字 |
| W4 网页服务器（终极） | 静态文件 + 脚本，多个客户端同时来，慢的不卡住别人 |

**挑战：** 慢客户端（一个客户端只发半个请求就不动了；naive 解：循环服务器，所有人都被卡住；跳跃：poll，谁准备好了处理谁）。

### 之后可以加：第 7 代 · 打开黑盒

前面用的系统调用都是黑盒。最后一代把它们打开：用环形缓冲实现管道、用表实现文件描述符和 dup2、写一个时间片轮转的调度器，再用前面各代的测试检查自己实现的内核。这和手册第 6 节的"封装件可以展开看内部"是同一个方向。

## 4. 元件从哪里来

- **原始元件**：系统调用（每一代的地基里一关出现一个），以及第 1 代的文本元件（匹配、拆字段、转成数、比较、排序）。
- **机体能力**（地基里教）：逐行跑板、寄存卡、管道台、目录遍历、两条泳道、事件循环。
- **学习者造的命令**（封装件）：cat、grep、wc、cut、sort、uniq、head、cp、mv、ls、du、find、timeout……每个都在后面的参考解里用到（审计 `unused`）。造出来的命令放进模拟文件系统的 /bin，第 3 代起由学习者自己的 shell 来跑。

## 5. 引擎：复用什么，补什么

**已经在 kit 里的（`games/kit/domains/unix/`，`npm test` 覆盖）：**

- `kernel.js`：确定性的模拟内核。文件系统（inode、目录、硬链接、unlink、rename）、打开文件描述（fork 和 dup 共享偏移量）、有容量的管道（写满阻塞，读端全关时写者被 SIGPIPE 杀掉）、进程（fork、exec、exit、wait、kill）。调度器每步随机挑一个能跑的进程（带种子，可以换着种子跑很多种交错）；谁都跑不了时报告"卡住"，并指出每个进程在等什么（读管道时列出还开着写端的进程）。
- `lines.js`：电传的逐行机器，就是共享引擎的 `walk`：每行跑一遍板，寄存器带到下一行，读完跑一次收尾板；文字元件（匹配、拆字段、转数、比较、放行、拼接）；`sort` 是声明的原始命令。
- `programs.js`：在内核里跑的程序：`cat`、整份输入的原始命令，以及把一块逐行板变成边读边处理的命令（它在内核里的输出和直接跑整份输入一样，测试里换五个种子核对）。
- `conformance/`：一致性用例（`cases.json`，11 个：共享偏移、unlink 后照读、硬链接、rename 覆盖、管道 EOF、忘关写端卡住、`> f 2>&1` 和 `2>&1 > f` 的区别、SIGPIPE、退出码）。模拟内核在 `npm test` 里跑，真的 Linux 由 `npm run conform`（`real.py`）跑，两边都要等于同一份期望。CI 两个都跑。
- 编辑器侧：线的种类（数据 / 句柄 / 次序，`parts.wireKind`）、板中板的路径（泳道用）。

**还没做的（按顺序）：**

1. **关卡界面和 `defineUnixGame`**：第 1 代的逐行电路关（几乎都能复用现有界面），然后是第 3 代的泳道原型。
2. **从电路板到内核程序**：现在内核跑的程序是 JS 生成器；把带次序线和泳道的电路编译成这样的程序，是第 2 代起要做的。
3. **调度的其余部分和故障注入**：有界的对抗调度、断电、拆包、虚假唤醒；线程、信号处理函数、套接字。
4. **时间线视图**和**文件描述符表 / 进程树 / inode 图**视图；代价度量（系统调用次数）。

**真机一致性检查：** 模拟内核的行为用一致性用例对照真的 Linux（`real.py`，Python 的 `os` 模块直接做系统调用），结果必须一致（`npm run conform`）。现在有 11 个用例，内核每多一种行为，就该多一个用例。这对应手册里"黑盒与搭出它的那一关一致"：模拟内核是整个游戏最大的黑盒，它和真机一致，游戏教的才是真的 Linux。

**诚实的限制：**

- 只模拟 POSIX 的一个子集：没有终端的行规程细节、mmap、真实的文件系统缓存。凡是简化过的地方，引入里要明说。
- 次序线是这个游戏和已有两款最不一样的地方，也是最没把握的交互。第 3 代的泳道同理。
- 对抗调度是有界搜索，找不到不等于没有。关卡的测试要配上已知的出错时间线（作为隐藏测试），保证 naive 解一定被抓到。

## 6. 建议的第一步

1. 先做第 1 代：几乎全靠现有 kit，能最早上线，也能验证"命令封装进 /bin"的感觉。
2. 紧接着单独做第 3 代 3-1 到 3-5 的原型：次序线和泳道是风险最大的两件事，要在写后面几代的逐关规格之前试出来。
